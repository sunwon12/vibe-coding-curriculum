# 바이브 코딩이란 무엇인가

## 한 줄로 말하면

**바이브 코딩(vibe coding)** = 코드를 직접 타이핑하는 대신, **말(자연어)로 AI에게 시켜서 실제로 돌아가는 걸 만드는 것**.

"바이브"는 "느낌·분위기"라는 뜻이에요. 문법 하나하나 신경 쓰기보다 **"이런 느낌으로 만들어줘"**라고 흐름 타듯 부탁한다고 해서 붙은 이름이에요.

이 말은 2025년 초, AI 연구자 **안드레이 카파시**(Andrej Karpathy, 오픈AI 창립 멤버)가 처음 썼어요.
그는 "AI가 너무 좋아져서, 이제는 그냥 **하고 싶은 걸 말하고, 실행하고, 결과를 보고, 다시 말하는** 식으로 프로그램이 만들어진다"고 했죠. 바로 이게 우리가 [[00_이-레포를-쓰는-법]]에서 본 **핵심 루프**예요.

## 스펙트럼: "순수 바이브" ↔ "이해하며 만들기"

바이브 코딩이라고 다 같은 게 아니에요. 두 극단 사이의 **넓은 띠**라고 생각하세요.

| | 순수 바이브 (왼쪽 끝) | 이해하며 만들기 (오른쪽 끝) |
|---|---|---|
| 태도 | 코드 안 읽고 AI가 준 걸 그대로 받음(Accept All) | AI가 만든 걸 읽고, 이해하고, 눌러서 테스트함 |
| 속도 | 아주 빠름 | 조금 느림 |
| 장점 | 재밌고 진입이 쉬움. 아이디어를 빨리 확인 | 뭐가 왜 됐는지 알아서, 커져도 안 무너짐 |
| 위험 | 앱이 커지면 어디가 왜 깨졌는지 모름 | (거의 없음, 대신 품이 듦) |
| 어울리는 때 | 장난감·프로토타입·주말 실험 | 남이 실제로 쓰는 앱, 데이터·로그인 다루는 앱 |

- **초보는 왼쪽에서 시작하는 게 맞아요.** 처음부터 코드를 다 이해하려 하면 겁만 나고 재미가 없어요. 일단 만들어지는 쾌감부터 느끼세요.
- 하지만 **앱이 조금 커지면 오른쪽 습관이 필요**해요 — 에러(빨간 글씨)를 읽어 보기, 잘 되던 지점을 저장해 두기(저장점), 버튼을 눌러 진짜 되는지 확인하기. (이건 개발자 사이먼 윌리슨이 강조한 태도이기도 해요.)
- **이 커리큘럼이 지향하는 자리는 딱 중간**이에요: **즐겁게 만들되, 최소한의 이해는 챙긴다.** 코치가 코드를 줄 때 "이게 무슨 일을 하는지" 한 줄씩 설명해 주는 것도 그래서예요.

## 왜 "지금" 이게 가능해졌나요

예전엔 프로그램을 만들려면 문법을 몇 달씩 배워야 했어요. 지금 되는 이유는 단 하나:

**LLM(대규모 언어 모델 — ChatGPT·Claude 같은 AI의 두뇌)이 코드를 충분히 잘 쓰게 됐기 때문이에요.**

이제 AI가 "할 일 목록 앱 만들어줘" 같은 말을 실제 코드로 바꿔 줄 수 있어요. 당신은 **무엇을 원하는지**만 또렷이 말하면 되고, **어떻게**는 AI가 채웁니다. 그래서 코딩 경험이 0이어도 시작할 수 있는 거예요.

## 이걸로 뭘 할 수 있나요 (그리고 뭘 조심하나요)

**잘 맞는 것 (신나게 하세요):**

- **프로토타입** — 아이디어가 진짜 될지 빠르게 확인하는 초벌 버전
- **개인용 도구** — 나만 쓰는 가계부·습관 기록·메모 앱
- **MVP**(Minimum Viable Product, 최소한만 돌아가는 첫 버전) — 남에게 보여주고 반응 볼 수 있는 정도
- **포트폴리오** — "내가 이런 걸 만들어 봤다"고 링크로 보여줄 결과물

**조심할 것 (알고만 있으면 돼요, 겁먹진 마세요):**

- **60~70%의 벽.** 처음 60~70%는 놀랄 만큼 빨라요. 그런데 마지막 30%(세밀한 버그·예외 상황)는 갑자기 느려져요. 이건 정상이고 누구나 겪어요. 이 벽을 넘는 법이 스텝08(디버깅)이에요.
- **진짜 개인정보·결제는 신중히.** 연습 단계에선 **실제 사람의 이름·연락처·카드번호를 넣지 마세요.** 가짜 예시 데이터로 충분해요.
- **보안.** 비밀번호·API 키(AI 서비스 이용 열쇠) 같은 비밀값은 코드에 그냥 쓰면 안 돼요. 이건 **코치가 알아서 환경변수(.env)로 안전하게** 빼줄 거예요. 당신이 신경 쓸 필요는 없지만, "그런 게 있구나" 정도만 알아 두세요.

## 마음가짐 3개 (제일 중요)

1. **완벽주의를 내려놓으세요.** 첫 버전은 못생겨도, 조금 어색해도 됩니다. 일단 돌아가게 만드는 게 이겨요.
2. **에러는 정상이에요.** 빨간 글씨는 "너 못한다"는 뜻이 아니라 "여기 이걸 고치면 돼"라는 안내문이에요. 그대로 코치에게 붙여넣으면 됩니다.
3. **"알아서 해줘"보다 구체적으로.** AI에게 통째로 맡길수록 결과물이 내 것에서 멀어져요. 다음 글에서 이 "구체적으로 말하는 법"을 제대로 배웁니다.
