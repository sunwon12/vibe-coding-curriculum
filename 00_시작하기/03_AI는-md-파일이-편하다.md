이 커리큘럼과 내 지식베이스의 파일은 전부 `.md`입니다. 왜 한글·워드가 아니라 md인지 알고 나면, AI에게 줄 자료를 어떤 모양으로 남길지 스스로 정할 수 있습니다.

`⭐ 쉬움 · 약 10분 · 코드 없음`

## md는 글자만 든 문서입니다

`.md`는 `.hwp`·`.pdf`처럼 파일 종류를 뜻하는 확장자이고, 마크다운(Markdown)의 줄임말입니다. 서식을 프로그램 안에 숨기지 않고 **글자 기호로 적어 둡니다.**

```mermaid
flowchart LR
  A["원본<br/># 노트북 고르는 기준<br/>- 가격: **50만 원 이하**"] -->|"뷰어로 열면"| B["큰 제목: 노트북 고르는 기준<br/>• 가격: 굵은 글씨로 50만 원 이하"]
```

| 원본에 적는 기호 | 뷰어에서 보이는 모양 |
| --- | --- |
| `# 제목` | 큰 제목 |
| `- 항목` | 점이 찍힌 목록 |
| `**강조**` | 굵은 글씨 |
| `\| 칸 \| 칸 \|` | 표 |

기호는 외우지 않아도 됩니다. 쓰는 건 AI가 합니다. 내가 알 것은 하나입니다. **메모장으로 열면 기호가 그대로 보이고, 뷰어로 열면 한글 문서처럼 보인다.** 이 과정에서는 Orca가 그 뷰어입니다([[04_AI-도구-고르고-CLI-설치하기]]).

## AI가 md를 편해하는 이유

| | 한글·워드·PDF | md |
| --- | --- | --- |
| AI가 읽을 때 | 글자를 뽑아내는 변환을 거치고, 표나 순서가 깨지기도 한다 | 받은 그대로 읽는다 |
| AI가 고칠 때 | 서식을 건드리다 파일이 깨지기 쉽다 | 글자를 바꾸듯 직접 고친다 |
| 필요한 부분만 찾을 때 | 문서 전체를 읽어야 한다 | `#` 제목을 보고 그 부분만 읽는다 |
| 여는 프로그램 | 한글·워드가 있어야 한다 | 메모장, 어떤 AI 도구든 열린다 |
| 바뀐 곳 확인 | GitHub에서 무엇이 바뀌었는지 안 보인다 | 바뀐 줄이 그대로 보인다 |

셋째 줄이 가장 중요합니다. AI의 기억 공간은 좁아서 문서를 통째로 넣을수록 흐려집니다. md는 제목으로 나뉘어 있어 **필요한 부분만 골라 읽힐 수 있습니다.** 그래서 지식베이스를 md로 씁니다.

## 직접 확인해 봅니다

1. GitHub 웹에서 이 커리큘럼의 `README.md`를 엽니다. 제목과 표가 정리된 모양으로 보입니다.
2. 파일 위쪽의 **Raw** 버튼을 누릅니다. `#`·`**`·`|`가 그대로 보이는 원본이 나옵니다.
3. 두 화면에서 같은 문장 하나를 찾아 비교합니다.

AI를 연결한 뒤에는 가지고 있던 한글·워드 문서도 md로 옮겨 지식베이스에 넣을 수 있습니다.

```text
[파일 경로]의 한글·워드 문서를 내용은 그대로 두고 md로 옮겨줘.
제목 구조와 표는 살리고, 옮기면서 빠지거나 깨진 부분이 있으면 따로 알려줘.
```

## 완료 기준

- md 원본에서 `#`와 `**`가 무엇을 뜻하는지 말할 수 있습니다.
- 같은 md 파일을 원본과 뷰어 두 모양으로 봤습니다.
- 지식베이스를 한글·워드가 아니라 md로 쓰는 이유를 한 문장으로 말할 수 있습니다.
