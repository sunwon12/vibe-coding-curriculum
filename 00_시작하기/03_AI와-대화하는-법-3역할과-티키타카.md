# AI와 대화하는 법 — 3역할과 티키타카

이 커리큘럼에서 **가장 중요한 글**이에요. 도구를 잘 다루는 것보다, **AI와 어떻게 대화하느냐**가 결과물을 가릅니다.
천천히, 예시를 손으로 따라 읽어 보세요.

## 핵심 태도: "해줘" 한 방보다 티키타카

초보가 가장 흔히 하는 실수는 **"쇼핑몰 만들어줘" 한 방**으로 끝내려는 거예요. AI는 뭔가 만들어 주긴 하는데, **당신이 상상한 것과 다르게** 나와요. 당신이 정보를 안 줬으니까요.

**티키타카(주고받는 대화)**가 실력이에요. 이건 "내가 프롬프트를 아주 길게 쓴다"는 뜻이 **아니에요.**
짧게라도 **여러 번 왕복하면서 맥락(상황·의도)을 쌓아 가는 것**이에요.

```
나: "할 일 목록 앱 만들고 싶어. 근데 어떻게 시작할지 모르겠어."
AI: "좋아요. 그 앱은 누가 써요? 나 혼자? 아니면 여러 명?"
나: "나 혼자, 하루 할 일 체크용."
AI: "그럼 할 일 추가 / 체크 / 삭제 이 세 개면 될까요?"
나: "응 딱 그거. 그걸로 시작하자."
```

이렇게 몇 번 주고받으면, AI는 **당신 머릿속 그림**을 정확히 알게 돼요. 결과물이 "내 것"이 됩니다.

## AI의 3가지 역할 (생각은 당신 것)

개발자 테오가 정리한 좋은 프레임이 있어요. AI를 **이 3가지 역할**로만 쓰세요:

| 역할 | 무슨 뜻 | 예시로 부탁하는 말 |
|---|---|---|
| ① **거친 생각을 문장으로 다듬기** | 머릿속 흐릿한 걸 또렷한 말로 | "이런 느낌인데 말로 잘 못 하겠어. 정리해 줄래?" |
| ② **각도 바꿔 되물어 판단 돕기** | 내가 놓친 걸 질문으로 짚어 줌 | "이 아이디어 별로인 점이 뭐야? 다른 방향도 물어봐 줘." |
| ③ **자료 찾아 주기** | 정보·예시·비슷한 사례 조사 | "비슷한 앱 어떤 게 있어? 참고할 만한 거 알려줘." |

**핵심: "무엇을·왜"는 당신이 정해요.** AI는 다듬고, 되묻고, 찾아 줄 뿐이에요.
생각을 통째로 던져서 AI가 다 정해 버리면, 나온 결과물은 **당신 것이 아니게** 돼요. 그럼 재미도, 배움도 사라져요.

## 프롬프트 공식 (복붙해서 [빈칸]만 채우세요)

상황은 크게 세 가지예요. 각각 공식이 있어요.

### (a) 새로 만들 때 — "4재료" 공식

**무엇 + 누구용 + 무슨 기능 + 어떻게 생겼는지**, 이 4가지를 넣으세요.

| 재료 | 질문 | 예시 |
|---|---|---|
| 무엇 | 뭘 만드나? | 방명록 웹페이지 |
| 누구용 | 누가 쓰나? | 내 블로그 방문자 |
| 무슨 기능 | 뭘 할 수 있나? | 이름과 한 줄 메시지를 남기고, 남긴 글이 아래에 쌓임 |
| 어떻게 생겼는지 | 분위기·참고 | 노션처럼 차분하고 심플하게, 흰 배경 |

- ❌ **나쁨:** "방명록 만들어줘" → AI가 뭘 만들지 몰라 아무거나 만들어요.
- ✅ **좋음 (복붙용):**
  ```
  방명록 웹페이지를 만들고 싶어.
  - 누가 쓰나: 내 블로그에 온 방문자
  - 기능: 이름이랑 한 줄 메시지를 입력해서 남기면, 아래에 방명록 글이 쌓여서 보여
  - 분위기: 노션처럼 차분하고 심플하게, 흰 배경
  일단 이대로 만들어줘. 로그인 기능은 없어도 돼.
  ```

### (b) 이미 있는 걸 고칠 때 — "위치 + 원하는 동작 + 건드리지 말 것"

만든 걸 수정할 땐, **어디를 · 어떻게 · 뭘 지킬지** 셋을 말하세요. 특히 **"건드리지 말 것"(가드레일)**이 중요해요 — 이게 없으면 잘 되던 다른 부분이 같이 망가지기도 하거든요.

- ✅ **좋음 (복붙용):**
  ```
  방명록 목록에서, 각 글 옆에 남긴 시간을 작게 회색으로 보여줘.
  - 위치: 글 목록의 각 글 오른쪽
  - 원하는 동작: "3분 전"처럼 상대 시간으로 표시
  - 건드리지 말 것: 글 입력창이랑 지금 색깔·배치는 그대로 둬
  ```

### (c) "계획 먼저" — 코드 짜기 전에 방향부터 맞추기

큰 걸 바꾸거나 새 기능을 붙일 땐, **바로 만들지 말고 계획부터** 듣는 게 안전해요.

- ✅ **복붙용:**
  ```
  아직 코드 짜지 마. 이걸 어떻게 만들지 계획부터 말로 설명해줘.
  괜찮으면 그때 "이대로 해줘"라고 할게.
  ```

이렇게 하면 AI가 엉뚱한 방향으로 한참 만들어 놓는 사고를 막을 수 있어요.

## 에러가 나면? (미리 알아 두는 습관)

빨간 글씨(에러)가 떠도 당황하지 마세요. 이렇게만 하면 돼요:

- **빨간 글씨를 그대로 복사**해서 채팅에 붙여넣고, 이렇게 말하세요:
  ```
  이런 에러가 났어. 아직 고치지 말고, 원인부터 쉬운 말로 설명해줘.
  ```
- **"아직 고치지 마"**가 포인트예요. AI가 원인을 먼저 짚게 하면, 당신도 무슨 일인지 이해하고 넘어갈 수 있어요.

## 대화 규칙 딱 3개

1. **한 번에 한 가지만.** 한 메시지에 "이것도, 저것도, 그리고" 몰아넣지 마세요. 하나 시키고 → 결과 보고 → 다음. 그래야 뭐가 깨졌는지 바로 알아요.
2. **구체적으로 (스크린샷·예시 주기).** "이상해"보다 "이 버튼을 눌렀는데 아무 일도 안 일어나"가 백 배 나아요. 화면 스크린샷을 붙이면 더 좋아요. Cursor 채팅엔 이미지도 넣을 수 있어요.
3. **안 되면 되돌리고 다시.** AI가 이상하게 고쳐서 더 엉켰다면, 계속 그 위에 덧대지(패치하지) 마세요. **잘 되던 지점으로 되돌린 뒤** 다시 또렷하게 부탁하는 게 빨라요. ("아까 잘 되던 상태로 돌아가고, 이번엔 이렇게 해줘.")
