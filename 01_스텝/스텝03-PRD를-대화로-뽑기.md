# 스텝03 — PRD를 대화로 뽑기

## 🎯 이 스텝에서 하는 일
코치와 **대화로** `02_템플릿/PRD.md`(만들 것을 적은 한 장짜리 기획서)를 채웁니다.

`⭐⭐ 보통 · 🕐 약 30분`

## 왜 이렇게 하나

PRD는 "Product Requirements Document"의 줄임말인데, 어렵게 생각 말고 **"뭘 만들지 한 장에 적은 계획서"**라고 보면 돼요. 집을 짓기 전에 그리는 **한 장짜리 도면**이죠.

초보가 바이브 코딩에서 실패하는 이유의 **대부분은 "AI가 내 의도를 몰라서"**예요. 머릿속에만 있는 걸 AI가 알 리 없거든요. 그래서 만들기 **전에** 뭘 원하는지 글로 정리해 두면, 이후에 AI가 훨씬 정확하게 만들어 줍니다. **기획 먼저, 코드는 그다음** — 이게 연구에서 나온 1순위 원칙이에요.

단, PRD를 혼자 문서와 씨름하며 오래 붙들 필요는 없어요. **코치가 항목별로 하나씩 물어보고, 당신은 대답만** 하면 됩니다. 대화가 곧 기획이에요. 그래서 이 단계에서는 코치에게 **"아직 코드는 짜지 마"**라고 못 박아 둡니다. 계획이 먼저니까요.

## 이렇게 하세요

1. **`02_템플릿/PRD.md` 파일을 엽니다.**
   - 항목마다 빈칸과 예시가 있어요. 코치와 함께 하나씩 채웁니다.

2. **코치에게 "계획 먼저 모드"로 부탁합니다.** (아래 프롬프트 복붙)
   - 코치가 **항목별로 하나씩** 물어봐요. 한꺼번에 다 묻지 않아요. 대답하기 편합니다.
   - 채울 항목: **한 문장 정의 / 누가 쓰나(타겟) / 핵심가치 / 꼭 필요한 기능 3개 / 이번엔 안 할 것 / 화면 목록.**

3. **"꼭 필요한 기능"을 3개로 줄입니다.**
   - 하고 싶은 게 많아도 지금은 3개만. 예(가계부): ① 지출 입력 ② 목록으로 보기 ③ 합계 보기.
   - 코치가 "이건 첫 앱엔 빼도 될까요?" 하고 되물어 줄이는 걸 도와줘요.

4. **"이번엔 안 할 것"도 꼭 적습니다.**
   - 이게 PRD의 숨은 핵심이에요. 예: "로그인은 이번엔 안 함", "카테고리 분류는 다음에", "예쁜 그래프는 나중에".
   - 안 할 걸 정해 두면 AI가 쓸데없는 걸 안 만들고, 당신도 안 헤맵니다.

5. **채워진 내용을 `PRD.md`에 남깁니다.** (코치가 정리해 줍니다)

## 🤖 AI(코치)에게 줄 프롬프트

```
내 앱 한 문장 정의는 이거야: [빈칸 - 스텝02에서 만든 한 문장]

이제 PRD.md(한 장짜리 기획서)를 채우고 싶어. 아직 코드는 절대 짜지 마.
다음 항목을 "한 번에 하나씩" 물어봐줘. 내가 대답하면 정리해서 PRD.md에 적어줘.

- 누가 쓰나 (타겟)
- 핵심가치 (이 앱이 주는 딱 하나의 좋은 점)
- 꼭 필요한 기능 3개 (더 많으면 3개로 줄이자고 되물어줘)
- 이번엔 안 할 것 (일부러 빼는 것들)
- 화면 목록 (몇 개의 화면이 필요한지)

기능이 많아지면 "첫 앱엔 이건 빼도 될까요?" 하고 줄이는 걸 도와줘.
```

## ✅ 여기까지 하면 이렇게 보여요

- `PRD.md`에 이 6가지가 채워져 있으면 성공이에요:
  **① 한 문장 정의 ② 타겟(누가 쓰나) ③ 핵심가치 ④ 필수 기능 3개 ⑤ 이번엔 안 할 것 ⑥ 화면 목록.**
- **기능이 3개를 넘어가면:** 코치에게 "이 중에 첫 앱에 꼭 없어도 되는 걸 골라 '안 할 것'으로 옮겨줘"라고 하세요.
- **막막하면:** 코치에게 "예시 PRD를 먼저 하나 보여주고, 그걸 참고해서 내 걸 채우자"라고 해보세요.

> 코치가 이 스텝을 눈으로 확인하면(PRD.md가 다 채워졌는지) `진행상태.md`를 `- [x]`로, `상태.json`을 갱신해 줍니다.

## ⚠️ 자주 하는 실수

- **기능을 3개로 못 줄이는 것.** 첫 앱은 작아야 완주해요. 나머지는 "안 할 것"으로.
- **"안 할 것"을 비워 두는 것.** 여기가 제일 중요해요. 뺄 걸 정해야 AI가 안 헤매요.
- **여기서 벌써 코드를 만들려는 것.** 계획이 먼저예요. 코치에게 "아직 코드 짜지 마"라고 하세요.
- **완벽한 문서를 쓰려고 오래 붙드는 것.** 대화로 후딱 뽑고, 부족하면 만들면서 고치면 돼요.
