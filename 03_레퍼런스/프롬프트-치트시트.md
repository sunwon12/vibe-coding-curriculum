# 프롬프트 치트시트 (복붙용)

> 막히거나 뭐라고 말해야 할지 모를 때 펴는 종이예요. 아래 블록을 **그대로 복사**해서 `[대괄호]` 안만 내 걸로 바꿔 붙여넣으세요.
> 대부분 바이브 코치가 알아서 이끌어주지만, 이 문서를 알아두면 코치가 없어도(예: Lovable) 혼자 진행할 수 있어요.

**한 줄 원리:** AI에게 `"알아서 다 해줘"`는 나쁜 프롬프트예요. **뭘 원하는지 구체적으로 말하는 게 실력**입니다.

---

## 1. 새로 만들 때 — "4재료" 공식  · [[스텝05-첫-화면-바로-뽑기]]

새 화면·앱을 처음 만들 땐 이 4가지를 꼭 넣어요. **무엇 + 누구용 + 무슨 기능 + 어떻게 생겼는지.**

### ❌ 나쁜 예 (AI가 엉뚱한 걸 만듦)
```
가계부 앱 만들어줘.
```
> 왜 나쁜가: 누가 쓰는지, 무슨 기능이 필요한지, 어떻게 생겨야 하는지가 없어요. AI가 마음대로 크고 복잡하게 만들어버려요.

### ✅ 좋은 예 (4재료 다 넣음)
```
[무엇]: 아주 간단한 가계부 웹앱의 메인 화면을 만들어줘.
[누구용]: 가계부 앱이 복잡해서 포기하는 나 혼자 쓸 거야.
[무슨 기능]:
- 항목(예: 커피)과 금액(예: 4500)을 한 줄로 입력하고 '추가' 버튼 누르기
- 추가한 내역을 최신순 목록으로 보여주기 (각 줄에 삭제 버튼)
- 맨 위에 이번 달 합계 크게 보여주기
[어떻게 생겼는지]: 노션처럼 차분하게, 흰 배경에 검정 글씨, 모바일에서도 안 깨지게.

저장은 일단 브라우저에만, 로그인은 없이. 지금은 이 화면 하나만 만들어줘.
```

### 복붙 템플릿
```
[무엇]: [만들 화면/앱을 한 줄로]
[누구용]: [실제로 누가 쓰나]
[무슨 기능]:
- [기능 1]
- [기능 2]
- [기능 3]
[어떻게 생겼는지]: [분위기 — 예: 노션처럼 / 블랙&화이트 / 파스텔], 모바일에서도 안 깨지게.

저장은 [브라우저에만 / 나중에 DB], 로그인은 [없이 / 나중에]. 지금은 이것만 만들어줘.
```

## 2. 이미 있는 걸 고칠 때 — "위치 + 원하는 동작 + 건드리지 말 것"  · [[스텝06-기능-붙이기-티키타카-루프]] · [[스텝09-다듬기-디자인과-라이브러리]]

이미 만든 걸 고칠 땐 **어디를(위치)** + **어떻게(동작)** + **뭘 건드리지 말지(가드레일)**를 줘요. 가드레일이 없으면 멀쩡한 걸 AI가 망가뜨려요.

### 복붙 템플릿
```
[위치]: [고칠 부분 — 예: 메인 화면의 '추가' 버튼 / 내역 목록의 각 줄]
[원하는 동작]: [어떻게 바뀌었으면 하는지 구체적으로]
[건드리지 말 것]: 나머지 기능과 디자인은 그대로 두고, 위에서 말한 것만 바꿔줘.
```

### ✅ 좋은 예
```
[위치]: 메인 화면의 내역 목록에서 각 줄
[원하는 동작]: 줄 오른쪽에 작은 'x' 버튼을 넣고, 누르면 그 내역이 삭제되고 이번 달 합계도 그만큼 줄어들게 해줘.
[건드리지 말 것]: 입력칸이랑 '추가' 버튼, 합계 디자인은 그대로 둬. 이 삭제 기능만 추가해줘.
```

## 3. 계획 먼저 시키기 (코드 짜기 전에)  · 모든 스텝에서 쓸 수 있음

큰 걸 바꾸거나 새 기능을 붙이기 전엔, **코드부터 짜지 말고 계획부터** 말하게 하세요. 방향이 틀리면 여기서 잡을 수 있어요.

### 복붙 템플릿
```
[내가 하려는 것]을 하고 싶어.
바로 코드 짜지 말고, 먼저 어떻게 할 건지 계획을 말로 설명해줘.
- 무슨 파일을 만들거나 고칠 건지
- 어떤 순서로 할 건지
- 내가 미리 정해야 할 게 있는지
계획 듣고 내가 "좋아 진행해"라고 하면 그때 코드를 짜줘.
```

## 4. 디버깅 세트 (막혔을 때)  · [[스텝08-막혔을때-에러-읽고-디버깅]]

빨간 에러가 떠도 정상이에요. 아래를 순서대로 써요. **한 번에 하나씩.**

### 4-1. 원인부터 설명시키기 (아직 고치지 말라고!)
```
아래 에러가 떴어. 에러 전문을 그대로 붙일게.
바로 고치지 말고, 먼저 이게 왜 생겼는지 원인을 쉬운 말로 설명해줘.
가능성 있는 원인을 3~4개 정도 짚어줘. 그다음에 어떻게 확인할지 알려줘.

[여기에 에러 전문(빨간 글씨 전체)을 그대로 붙여넣기]
```

### 4-2. 지금까지 시도한 것 정리해서 주기
```
아까 그 문제 아직 안 풀렸어. 지금까지 이렇게 해봤어:
- [시도 1 → 결과]
- [시도 2 → 결과]
다시 원인을 좁혀서, 다음에 뭘 해보면 좋을지 하나만 알려줘.
```

### 4-3. 로그(중간 확인 메시지) 추가해서 원인 찾기
```
어디서 잘못되는지 아직 모르겠어.
문제되는 부분에 '지금 여기까지 왔다', '이 값은 이거다'를 화면이나 콘솔에 찍는 로그를 넣어줘.
그걸 보고 어디서 멈추는지 같이 찾자.
```

### 4-4. 되돌리기 (더 나빠졌을 때)
```
방금 바꾼 것 때문에 오히려 더 망가졌어.
방금 수정을 되돌려서(원래대로), 바꾸기 직전 상태로 돌려줘.
그다음 다른 방법으로 다시 시도하자.
```

## 5. 디자인 다듬기 — 근거 있는 단순 프롬프트  · [[스텝09-다듬기-디자인과-라이브러리]]

디자인은 어려운 말 필요 없어요. **아는 제품 이름**을 대는 게 제일 잘 먹혀요.

### 복붙 템플릿 (골라 쓰기)
```
전체 톤을 블랙 & 화이트로 깔끔하게 정리해줘. 색은 최소한만 쓰고, 글씨랑 여백으로 정돈되게.
```
```
노션(Notion)처럼 차분하고 심플하게 만들어줘. 여백 넉넉하게, 글씨 크기는 읽기 편하게.
```
```
모바일(휴대폰 화면)에서 안 깨지게 만들어줘. 버튼이랑 글씨가 화면 밖으로 넘치지 않고, 손가락으로 누르기 편한 크기로.
```
```
버튼이랑 입력칸을 shadcn/ui의 기본 컴포넌트로 바꿔서 통일감 있게 만들어줘. 나머지 기능은 그대로 두고.
```
> 팁: 한 번에 다 바꾸지 말고 하나씩. "이번엔 색만", "이번엔 여백만" 이렇게.

## 6. 데이터 · 배포  · [[스텝07-데이터-저장하기-DB붙이기]] · [[스텝10-배포-남에게-URL-보내기]]

이 부분은 보통 **코치가 대신 실행**해요. 아래는 코치에게 부탁하거나, 혼자 진행할 때 쓰는 프롬프트예요.

### 6-1. Supabase 붙이기 (브라우저 저장 → 진짜 DB로)
```
지금은 데이터가 브라우저에만 저장돼서 새로고침하거나 다른 기기에서 열면 사라져.
이걸 Supabase(무료 데이터베이스)에 저장하도록 바꿔줘.
- 바로 코드 짜지 말고, 먼저 무슨 순서로 할지 계획부터 말해줘 (내가 Supabase에서 뭘 해야 하는지 포함).
- 비밀 키는 코드에 직접 쓰지 말고 환경변수(.env)로 빼줘.
```

### 6-2. 환경변수 안전하게 (비밀 키 숨기기)
```
방금 받은 [API 키 / 비밀번호 / 접속 주소]를 코드에 직접 쓰지 말고 .env 파일로 빼줘.
그리고 .env가 실수로 인터넷에 올라가지 않게 .gitignore에 꼭 넣어줘.
어떤 값을 어디에 넣어야 하는지 나한테 한 줄로 알려줘.
```
> ⚠️ 실제 사람의 개인정보(진짜 이름·전화번호·주소)는 넣지 마세요. 연습이니까 가짜 데이터로.

### 6-3. GitHub + Vercel로 배포하기 (인터넷에 올려 링크 만들기)
```
이 앱을 인터넷에 올려서 친구에게 링크로 보낼 수 있게 배포하고 싶어.
GitHub에 올리고 Vercel(무료 배포)로 배포하는 걸 도와줘.
- 바로 하지 말고, 순서를 먼저 설명해줘 (내가 눌러야 하는 버튼 포함).
- .env의 비밀 값들은 Vercel 설정에도 넣어야 하니, 그것도 챙겨줘.
전부 무료 범위 안에서 되게 해줘.
```
