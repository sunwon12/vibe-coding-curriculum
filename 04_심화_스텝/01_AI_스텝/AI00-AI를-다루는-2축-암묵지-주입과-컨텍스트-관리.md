# AI00 — AI를 다루는 단 두 개의 축: 암묵지 주입과 컨텍스트 관리

## 🎯 이 스텝에서 하는 일

AI를 쓸 때 **내가 실제로 손댈 수 있는 게 딱 두 개**뿐이라는 걸 이해하고, 실험 4개로 직접 확인합니다.
이게 잡히면 앞으로 듣게 될 모든 AI 용어(토큰·RAG·MCP·에이전트·파인튜닝·환각…)가
**새로 외울 것이 아니라 이 둘 중 하나에 걸리는 것**이 돼요.

`⭐ 쉬움 · 🕐 약 25분` · 💡 **코드 없음. 읽고 실험만.** AI 트랙의 0번 — 이걸 먼저 하면 나머지가 다 쉬워져요.

## 🔔 이 모듈이 필요한 신호

- AI가 어떤 건 기막히게 잘하고 어떤 건 어이없이 틀리는데, **그 경계가 어디인지 감이 안 온다.**
- 새 용어를 들을 때마다 처음 듣는 말 같다. 지식이 **쌓이지 않고 흩어진다.**
- AI 답이 늘 **"교과서 같은 일반론"**이고, 내 사정에 맞는 얘기가 안 나온다.
- 대화가 길어지면 **아까 정한 걸 까먹는다.**

---

## 먼저: 못 바꾸는 것 두 개 (전제)

축을 말하기 전에, **아무리 애써도 내가 못 바꾸는 것 두 개**를 털고 갑시다.
이걸 붙잡고 씨름하는 게 초보가 시간을 가장 많이 버리는 지점이에요.

### 전제 ① AI는 얼어붙은 수식이다 — 나를 모르고, 나에게 배우지 않는다

AI는 "아는 사람"이 아니라 **숫자 손잡이(파라미터)가 수천억 개 달린 고정된 수식**이에요.
어마어마한 양의 글을 읽히며 "이 말 다음엔 이런 말이 오더라"가 맞아떨어지도록 손잡이를 자동으로 맞춰 둔 것이고,
**학습이 끝난 순간 그 손잡이는 얼어붙습니다.**

그래서:

- 당신과 아무리 오래 대화해도 **손잡이는 1밀리미터도 안 돌아가요.**
- 오늘 고쳐 준 걸 내일 그 모델이 기억하고 있지 않아요.
- 당신 회사 사정, 당신 앱 사정, 당신 취향은 **당연히 모릅니다.** 세상 어디에도 안 적힌 이야기니까요.

> 이게 왜 중요하냐면, 여기서 **결론이 딱 하나로 좁혀지기 때문**이에요.
> 수식은 못 바꾼다 → **내가 바꿀 수 있는 건 거기 뭘 넣느냐뿐이다.**
> "AI를 잘 쓴다"는 말은 사실상 **"입력을 잘 만든다"**는 뜻이고, 그게 아래 두 축의 전부예요.

### 전제 ② AI는 확률로 말을 잇는다 — 그래서 자신 있게 틀린다

AI는 저장된 정답을 찾아오는 게 **아니라**, 지금까지의 글을 보고 **"다음에 올 법한 말"을 한 조각씩 이어 붙여요.**

- 모르면 침묵하는 구조가 아니라서, **없는 기능·없는 주소·없는 함수를 아주 당당하게 만들어 냅니다**(환각).
- 같은 질문에 매번 조금씩 다르게 답하는 것도 고장이 아니라 원래 그런 구조예요.
- **유창함과 정확함은 별개예요.** 말투가 확신에 차 있다고 맞는 게 아닙니다.

이 성질도 못 바꿔요. 줄일 순 있어도(→ 축1·축2로) **0으로는 안 됩니다.**
그래서 이건 축이 아니라 맨 아래 **"안전선"**으로 따로 둡니다.

## 그래서 내가 손대는 레버는 둘뿐이다

```
       [ 못 바꾸는 전제 ]  얼어붙은 수식 · 확률로 잇는 말
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
   축 1 — 주입              축 2 — 컨텍스트 관리
  "무엇을 넣는가"           "유한한 공간을 어떻게 쓰는가"
  내 머릿속에만 있는 것을     책상은 좁다. 무엇을 올리고
  꺼내서 읽게 만들기          무엇을 치우고 어디에 집중시킬지
        └───────────┬───────────┘
                    ▼
            [ 안전선 ] 나온 것은 내가 확인한다
```

| | 축 1 — **주입** | 축 2 — **컨텍스트 관리** |
|---|---|---|
| 한 줄 | **무엇을** 넣는가 (내용) | **얼마나·언제·어디에 집중**시키는가 (운용) |
| 다루는 문제 | AI가 나를 모른다 | 공간이 유한하고, 어지르면 흐려진다 |
| 실패하면 | 답이 **일반론**이 된다 | 답이 **엉뚱해지고 앞을 까먹는다** |
| 대표 행동 | 내 기준·사례·맥락을 글로 꺼내 놓기 | 필요한 것만 올리기 · 새 대화 · "이것만 봐" |

**이 둘은 서로 다른 문제예요.** 좋은 재료를 잔뜩 만들어 놓고 한꺼번에 쏟으면 축2에서 망하고,
책상을 아무리 깔끔히 써도 넣을 재료가 없으면 축1에서 망합니다.

|  | **책상 어지름** | **책상 깔끔** |
|---|---|---|
| **재료 없음** | 😵 대부분의 사람. 길게 떠들었는데 일반론만 | 🙂 깔끔한 **일반론**. "프롬프트 기술"만 익힌 상태 |
| **재료 있음** | 😤 좋은 걸 줘도 못 찾음. 지식베이스 만들어 놓고 통째로 쏟는 경우 | 🎯 **"내 것"이 나온다** |

## 축 1 — 주입: 내 머릿속에만 있는 것을 꺼내 주기

AI가 모르는 건 두 종류예요.

1. **세상에 적혀 있지만 얘가 아직 못 본 것** — 최신 뉴스, 새로 나온 도구. (도구를 붙여 검색시키면 해결)
2. **세상 어디에도 안 적힌 것** — 우리 팀이 왜 그 결정을 했는지, 내가 뭘 싫어하는지, 이 앱의 사용자가 누구인지,
   지난번에 이렇게 했다가 망했다는 것. ← **이게 암묵지고, 축1의 본진이에요.**

2번은 **내가 꺼내 주지 않으면 세상 누구도 못 줍니다.** AI가 늘 교과서 같은 답만 하는 이유가 이거예요.
얘는 최선을 다하고 있어요. **재료가 평균값밖에 없으니 평균값이 나오는 것뿐.**

### 무엇을 주입하나 (거의 다 여기 들어갑니다)

| 종류 | 예 |
|---|---|
| **나·우리** | 내가 누구고 무슨 일을 하는지, 이 앱을 누가 쓰는지 |
| **기준·취향** | "나는 이런 말투를 싫어한다", "우리는 화려한 디자인 안 쓴다" |
| **지난 결정과 그 이유** | "로그인은 일단 안 넣기로 했다 — 왜냐면…" ← **이유가 핵심이에요** |
| **실패 기록** | "이렇게 했다가 깨졌다" — AI가 같은 함정을 다시 파지 않게 |
| **현재 상태** | 지금 어디까지 만들었는지, 뭐가 되고 뭐가 안 되는지 |

### 주입하는 방법 두 가지

- **매번 책상에 올리기** — 파일로 적어 두고 AI가 매 대화에서 읽게 하기.
  **일반인이 쓰는 방법은 사실상 이것 하나뿐이고, 이걸로 충분해요.**
  → [[AI01-지식자산화-AI에게-줄-지식베이스-만들기]](큰 그림) · [[AI02-AI가-안-헤매게-규칙과-계획-고정하기]](축소판·실전)
- **손잡이를 다시 돌리기(파인튜닝)** — 얼어붙은 모델을 조금 다시 학습시키는 것.
  비싸고 손이 많이 가고, **초보가 겪는 문제의 열에 아홉은 위 방법으로 해결돼요.** 이름만 알아 두고 넘어가세요.

> 💡 **"말로 하지 말고 파일로"가 축1의 제1원칙이에요.**
> 같은 설명을 세 번 했다면, 그건 대화가 아니라 **파일에 적을 내용**이라는 신호예요.
> 말로 하면 매번 조금씩 달라지고, 새 대화창을 열면 통째로 사라져요.

## 축 2 — 컨텍스트 관리: 유한한 책상을 어떻게 쓸 것인가 ⭐

가장 흔한 오해부터 깨고 갈게요.

> ❌ "AI가 우리 대화를 기억한다"
> ✅ **"AI는 답할 때마다 대화 전체를 처음부터 다시 읽는다"**

AI에겐 기억이 없어요. 대신 말을 걸 때마다 **지금까지 오간 것 전부를 통째로 다시 넣어 주는** 거예요.
5번째 질문을 하면 그 순간 AI는 1~4번 대화 + 5번 질문을 **한꺼번에 처음 보는 것처럼** 읽고 답합니다.

그러니 이 그림이 맞아요. **AI에게 책상 하나가 할당돼 있고, 대화할수록 그 위에 종이가 쌓입니다.**

```
[책상 = 컨텍스트]  ← 답할 때마다 이 책상을 통째로 다시 훑는다

 ┌──────────────────────────────────────┐
 │ 규칙·지식 파일  ← 축1이 넣어 둔 재료      │
 │ 내가 한 말 1 / AI 답 1                 │
 │ 내가 한 말 2 / AI 답 2                 │
 │ 붙여넣은 에러, 스크린샷                 │
 │ 도구가 읽어 온 파일 내용                │
 └──────────────────────────────────────┘
      책상 크기는 정해져 있다 = 컨텍스트 윈도우
      그 분량을 재는 단위 = 토큰 (요금·속도도 여기 비례)
```

여기서 실전 규칙 세 개가 나와요.

**① 책상은 유한하다 — 넘치면 오래된 게 밀려난다.**
**"대화가 길어지니까 아까 정한 규칙을 까먹더라"의 진짜 원인이 이거예요.**
AI가 게을러진 게 아니라 **그 종이가 책상에서 밀려난 것.**
→ 그래서 규칙은 말로 하지 말고 **매 턴 자동으로 다시 올라가는 파일**로 박아 둡니다([[AI02-AI가-안-헤매게-규칙과-계획-고정하기]]).

**② 책상이 넓어도, 어지르면 성능이 떨어진다.**
"창이 크니까 다 넣으면 되겠네"는 함정이에요. 관계없는 자료가 잔뜩 깔리면 AI는 **뭘 봐야 할지 흐려집니다.**
사람도 책상에 서류 300장 깔면 오히려 못 찾잖아요. 게다가 느려지고 비싸져요.
**축1을 잘한 사람이 여기서 자주 망해요** — 좋은 재료를 만들어 놓고 통째로 쏟거든요. **고르는 게 실력입니다.**

**③ 그래서 "무엇에 집중하라"고 말해 주는 게 일의 절반이다.**
자료를 주는 것만큼, **지금 볼 것과 안 볼 것을 갈라 주는 것**이 중요해요.

- ✅ "**이 파일만** 보고 고쳐. 다른 건 열지 마."
- ✅ "**목록 화면만** 손대고, 입력창이랑 색깔은 **건드리지 마.**"
- ✅ "지금부터 결제 얘기만 할 거야. 앞의 디자인 얘기는 **잊고** 이것만 봐."

### 책상을 아껴 쓰는 5가지 방법

방법은 결국 다섯 묶음이에요. **비운다 · 좁힌다 · 눌러 담는다 · 고정한다 · 남에게 시킨다.**

| 묶음 | 구체적으로 | 언제 쓰나 |
|---|---|---|
| **① 비운다** | **새 대화 열기**(`/clear`) — 완전 초기화 | 기능·주제가 바뀔 때. **가장 확실하고 가장 안 쓰는 방법** |
| | **compact(자동 요약)** — 눌러 담기 | 지금 흐름은 이어가야 하는데 길어졌을 때 |
| | **손으로 요약해서 이관** — "지금까지 정한 것만 10줄로 정리해줘" → 새 창에 붙여넣기 | compact보다 **내가 뭘 남길지 고를 수 있음.** 중요한 작업일수록 이쪽 |
| **② 좁힌다** | **읽을 것 지정** — "이 파일만 봐" | 항상. AI는 안 막으면 이것저것 열어 봅니다 |
| | **건드릴 것 지정(가드레일)** — "목록만 고치고 입력창은 두고" | 고칠 때 항상 |
| | **찾을 말 대신 주기** — "`결제` 들어간 데를 찾아봐" | 막연히 탐색시키면 파일을 왕창 읽어 책상을 다 먹어요 |
| **③ 눌러 담는다** | **전문 대신 발췌** — 로그 3,000줄 말고 **에러 난 20줄** | 붙여넣기 전에 항상 |
| | **경로만 주기** — 파일 내용을 복붙하지 말고 "이 파일 읽어봐" | 도구가 붙은 환경(Cursor 등) |
| | **표·목록으로 주기, 같은 말 반복 안 하기** | 긴 설명을 줄 때 |
| **④ 고정한다** | **규칙 파일**(AGENTS.md) — 매 턴 자동으로 다시 올라옴 | 매번 반복할 말은 전부 |
| | **계획·진행 파일** — 정한 것과 지금까지 한 것을 파일에 적기 | 작업이 하루를 넘어갈 때 |
| **⑤ 남에게 시킨다** | **서브에이전트** — 조사는 **딴 책상**에서 하고 결론만 받기 | 자료를 많이 뒤져야 할 때 → [[AI03-MCP와-서브에이전트로-워크플로-자동화]] |

> ⚠️ **compact를 믿고 미루지 마세요.** compact는 **손실 압축**이에요 — 눌러 담는 과정에서 세부가 날아갑니다.
> **중요한 결정은 compact 전에 파일로 먼저 빼 두세요.** 순서로 치면 **④(고정)를 해 두고 나서 ①(비우기)**예요.

> 📌 **한 줄로 줄이면 이겁니다.**
> **대화창을 기억 저장소로 쓰지 마세요. 저장소는 파일이고, 대화창은 작업대예요.**
> 작업대는 원래 자주 치우는 물건이에요. 파일에 남겨 뒀다면 **치워도 아무것도 안 잃습니다.**
> 대화창에만 있는 걸 아까워하는 순간, 어질러진 책상을 못 버리게 돼요.

### 놓기 순서도 중요해요

같은 내용이라도 **어디에 놓느냐**에 따라 다르게 먹혀요. 책상 **가운데는 흐려지고, 맨 앞과 맨 끝이 선명**하거든요.

- **긴 자료는 먼저, 질문은 맨 마지막에.** ("자료 → 그래서 뭘 해달라" 순서. 반대로 하면 질문이 파묻혀요.)
- **가장 중요한 지시는 맨 끝에 한 번 더.** 직전에 한 말이 제일 세게 먹힙니다.

## 안전선 — 나온 것은 내가 확인한다

두 축을 아무리 잘해도 **전제②(확률로 잇는다)는 안 없어져요.** 그래서 마지막 한 겹이 남습니다.

> **그럴듯함 ≠ 맞음. 검증은 언제나 내 몫이다.**
> 화면에서 직접 눌러 보고, 에러를 읽고, **눈으로 본 것만 완료**예요.
> (이 커리큘럼의 코치가 "다 됐어요"라는 말만으론 체크를 안 해 주는 이유가 이거예요.)

줄이는 방법은 **결국 두 축으로 돌아와요** — 근거 자료를 같이 올리고(축1·2), "모르면 모른다고 해"를 규칙에 박고(축1),
도구로 실제 확인시키기(아래). 하지만 **0으로는 안 되니까** 마지막은 사람이 봅니다.

반대로 이 성질이 **강점이 되는 일**도 분명해요. 형식 맞추기, 문장 다듬기, 번역, 요약, 후보 스무 개 쏟아내기,
비슷한 코드 반복해 찍어내기 — 여기선 사람이 못 이깁니다.
**"정확한 사실"은 의심하고, "그럴듯한 형태"는 맡기세요.**

## 도구·MCP·에이전트는? — 두 축의 자동화 수단

수식 자체는 **글자만 뱉어요.** 파일을 못 열고, 인터넷을 못 보고, 명령을 못 칩니다. 원래는요.
그런데 Cursor는 실제로 내 파일을 고치잖아요. 그건 옆에 붙은 프로그램이 대신 손이 돼 주기 때문이에요.

```
AI "이 파일 열어줘" → 프로그램이 진짜로 열어서 → 그 내용을 책상에 올려 준다 → AI가 읽고 다음을 시킨다 (반복)
```

- 그렇게 밖에 붙여 준 능력이 **도구(tool)**, 그걸 표준 규격으로 꽂는 콘센트가 **MCP**,
  저 반복 루프를 도는 놈이 **에이전트**예요. → [[AI03-MCP와-서브에이전트로-워크플로-자동화]]
- **핵심은 이거예요. 도구는 새로운 축이 아니라, 축1·축2를 손으로 안 하고 자동으로 하는 방법이에요.**
  - 내 노션·DB를 AI가 직접 읽는다 = **축1(주입)의 자동화**
  - 필요한 파일만 그때그때 찾아 읽는다 = **축2(관리)의 자동화**
- 그래서 **도구가 읽어 온 것도 결국 책상을 먹어요.** 많이 읽힐수록 책상이 훅훅 찹니다 — 축2 문제로 되돌아와요.
- 그리고 손이 생겼다는 건 **진짜로 지울 수도 있다는 뜻**이에요. 저장점([[제품01-버전관리-Git-되돌리기]])과 실행 전 승인이 안전벨트.

## 🧪 직접 확인하기 — 실험 4개 (각 2분)

읽어서 아는 것과 겪어서 아는 건 달라요. 지금 쓰는 AI에 그대로 해 보세요.

**실험 1 (축1) — 주입 전 / 주입 후**
새 대화창에서 먼저 이렇게만 물어보세요: **"나한테 맞는 사이드 프로젝트 하나 추천해줘."**
→ 뻔한 일반론이 나옵니다. 당연해요, 얘는 당신을 모르니까.
이제 같은 창에 **내 상황을 5줄** 적어 주세요(직업·쓸 수 있는 시간·싫어하는 것·해 본 것·목표). 그리고 다시 물어보세요.
→ **답이 통째로 달라집니다.** 모델은 그대로인데 재료만 바뀐 거예요. 이게 축1의 전부예요.

**실험 2 (축1·전제①) — 기억은 어디에 있나**
실험1에 이어서, **새 대화창을 열고** "아까 내 상황 기억나?"라고 물어보세요.
→ 백지입니다. **기억은 모델이 아니라 책상에 있었어요.**
→ 그래서 매번 다시 올릴 방법(=파일)이 필요한 거예요.

**실험 3 (축2) — 책상에서 밀려나는 순간**
대화 맨 처음에 이렇게 말해 두세요: **"앞으로 모든 답 끝에 🍋를 붙여줘."**
그리고 다른 주제로 한참(20~30번) 대화해 보세요.
→ 어느 순간 🍋가 사라집니다. **그게 그 종이가 밀려난 순간**이에요.
→ 이걸 겪고 나면 [[AI02-AI가-안-헤매게-규칙과-계획-고정하기]]가 왜 필요한지 몸으로 압니다.

**실험 4 (안전선) — 환각을 직접 보기**
**존재하지 않는 것**을 진지하게 물어보세요. 예: "리액트의 `useMagicForm` 훅 사용법 알려줘."
→ 없다고 하면 다행이고, **그럴듯한 예제를 지어내면 그게 환각**이에요. 이어서 물어보세요:
"방금 그거 진짜 있는 거야? 확실한 것과 추측을 나눠서 말해줘."

## 🧭 새 지식이 오면 — 2축 라우팅 표

앞으로 어디선가 새 용어를 들으면, 외우기 전에 **"둘 중 어디지?"부터** 물어보세요.

| 들은 말 | 어디에 걸리나 | 실은 이런 얘기 |
|---|---|---|
| 컨텍스트 / 컨텍스트 윈도우 | **축2** | 책상 그 자체와 그 크기 한계 |
| 토큰 | **축2** | 책상 위 분량을 재는 단위(= 요금·속도) |
| 새 대화 열기 / 요약 / compact | **축2** | 책상을 갈아엎거나 눌러 담기 |
| "이 파일만 봐" / 건드리지 마 | **축2** | 어디에 집중할지 지정 |
| 지식베이스 / 노트 / 나에-대해 | **축1** | 암묵지를 꺼내 재료로 만들기 |
| 시스템 프롬프트 / AGENTS.md / Rules | **축1 + 축2** | 내용은 주입, **매 턴 자동 재적재**는 관리 |
| RAG | **축1 + 축2** | 재료를 쌓아 두고(1) **필요한 것만 골라 올림**(2) |
| 파인튜닝 | **축1의 비싼 변종** | 책상이 아니라 손잡이에 직접 새기기. 일반인 영역 아님 |
| 첨부·스크린샷·멀티모달 | **축1** | 넣을 수 있는 재료의 **종류**가 늘어난 것 |
| MCP / 툴 / 함수 호출 | **두 축의 자동화** | 주입과 선별을 사람 손 대신 자동으로 |
| 에이전트 / 서브에이전트 | **두 축의 자동화** | 그 자동화를 스스로 반복하는 놈 |
| 모델 크기 / 버전 / 컷오프 | **전제①** | 못 바꿈. 고르기만 함 |
| 환각 / temperature / 매번 다른 답 | **전제② → 안전선** | 못 없앰. 줄이고 **확인**함 |

**판별 질문 3개** — 이 순서로 물으면 거의 다 걸립니다.

1. 이게 **무엇을 넣을지**에 관한 얘긴가? → **축1(주입)**
2. **얼마나·언제·어디에 집중**할지에 관한 얘긴가? → **축2(관리)**
3. 둘 다 아니면 → **못 바꾸는 전제**이거나, **두 축을 자동화하는 수단**이거나, **확인해야 할 안전선.**

## 그래서 실전에서 뭐가 달라지나

결과가 나쁠 때 **"모델이 멍청해서"라고 결론짓지 마세요.** 순서를 이렇게 바꾸면 대부분 첫 줄에서 끝납니다.

> **1순위 — 재료를 안 줬나? (축1)** "얘가 알 리 없는 걸 알 거라고 기대했나?"
> **2순위 — 책상이 어질러졌나? (축2)** "쓸데없는 게 잔뜩 올라가 있거나, 중요한 게 밀려났나?"
> **3순위 — 확인 안 하고 믿었나? (안전선)**
> 4순위 — 그제야 "모델을 바꿔 볼까?"

그리고 이 트랙의 나머지 모듈이 전부 이 두 축 위에 있어요.

- [[AI01-지식자산화-AI에게-줄-지식베이스-만들기]] → **축1의 본진.** 암묵지를 꺼내 재료로 만드는 일.
- [[AI02-AI가-안-헤매게-규칙과-계획-고정하기]] → **축1을 축2로 굳히는 일.** 재료가 매 턴 자동으로 올라오게.
- [[AI03-MCP와-서브에이전트로-워크플로-자동화]] → **두 축의 자동화.** 사람 손 대신 도구가.
- [[AI04-코드-읽고-AI-졸업하기]] → **안전선.** 나온 걸 내가 읽고 판단할 수 있게.

## 🤖 AI(코치)에게 줄 프롬프트

**새 용어를 만났을 때 — 이게 이 모듈의 핵심 프롬프트예요.**
```
[○○]이 뭐야? 설명하기 전에, 이게 "내가 무엇을 넣을지(주입)" 얘긴지 "유한한 컨텍스트를 어떻게 쓸지(관리)"
얘긴지, 아니면 둘 다 아닌 전제·수단인지부터 한 줄로 말해줘. 그다음 비유로 쉽게 설명해줘.
```

**축1 — 내 암묵지를 꺼낼 때**
```
지금 이 프로젝트에 대해 네가 모르면 헤맬 것 같은 게 뭐야? 나한테 질문을 5개 던져줘.
내가 답하면 그걸 파일로 정리해서, 앞으로 매번 읽을 수 있게 만들어줘.
```

**축2 — 책상 상태를 점검할 때**
```
지금 이 대화에 뭐가 쌓여 있는지 요약해줘. 그중 지금 하려는 작업([무슨 작업])에 필요 없는 건 뭐야?
새 대화로 옮기는 게 나을까? 옮긴다면 뭘 들고 가야 해?
```

**안전선 — 믿기 전에**
```
방금 답에서 확실한 것과 네 추측을 나눠서 다시 말해줘. 추측인 부분은 어떻게 확인하면 되는지도 알려줘.
```

## ✅ 여기까지 하면 이렇게 보여요

- **두 축을 안 보고 말할 수 있어요** — 무엇을 넣는가(주입) / 유한한 공간을 어떻게 쓰는가(관리).
- 실험 1에서 **주입 전후로 답이 뒤집히는 걸** 직접 봤어요. 실험 3에서 **🍋가 사라지는 순간**을 봤고요.
- 새 용어를 들으면 **"이건 주입 얘기네 / 관리 얘기네"**를 먼저 말할 수 있어요.
- AI가 헛소리를 하면 짜증 내는 대신 **"내가 뭘 안 줬지?"**를 먼저 묻게 돼요.

> 코치는 위 네 가지를 학습자가 **자기 말로 설명하는 걸 듣고 나서** `진행상태.md`의 이 줄을 `- [x]`로, `상태.json`을 갱신해 줍니다.
> (요약을 읽어 주는 걸로는 통과가 아니에요. 전제②에서 봤듯 **유창함은 이해의 증거가 아니니까요.**)

## ⚠️ 자주 하는 오해

- **"AI가 나를 기억한다."** → 매번 다시 읽는 거예요. 새 창은 백지.
- **"대화가 길수록 AI가 나를 더 잘 안다."** → 어느 선을 넘으면 **오히려 나빠져요.** 앞이 밀려나고 초점이 흐려집니다.
- **"창이 크니까 다 넣으면 된다."** → 넣을수록 흐려지고, 느려지고, 비싸져요. **축1을 잘한 사람이 여기서 망합니다.**
- **"내가 고쳐 말해 줬으니 다음부터 안 그러겠지."** → 이 대화 안에서만이에요. → 그래서 **파일로**(축1).
- **"AI가 검색해서 답한다."** → 도구가 붙어 있지 않으면 아니에요. 그냥 그럴듯하게 잇는 겁니다.
- **"틀린 답 = 나쁜 모델."** → 대개는 **재료를 안 준 것**이거나 **책상이 어질러진 것**이에요.
- **"어려운 걸 잘하니 쉬운 것도 당연히 잘하겠지."** → 자릿수 계산·글자 수 세기 같은 게 **오히려 틀려요.** 잘하는 일과 못하는 일의 경계가 사람과 다릅니다.
