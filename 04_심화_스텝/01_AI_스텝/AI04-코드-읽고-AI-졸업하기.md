# AI04 — 코드 읽고 'AI 졸업하기'

## 🎯 이 스텝에서 하는 일 (한 줄)
코드가 **뭘 하는지 읽는 법**을 익히고, 어디까지 AI로 가고 **언제 개발자를 부를지** 판단합니다.

`⭐⭐⭐ 어려움 · 🕐 약 40분`

## 🔔 이 모듈이 필요한 신호
- 사용자가 **실제로 붙었다** — 이제 부수면 진짜 누군가 불편해진다.
- **두더지잡기**(하나 고치면 셋이 깨지는 무한 루프)에 시간을 다 쓰고 있다.
- 내 코드가 뭘 하는지 **하나도 모르는 게 불안**해졌다.

## 왜 이렇게 하나

먼저 정직하게. "바이브 코딩"이라는 말을 처음 만든 안드레이 카파시(Andrej Karpathy)가 원래 뜻한 건 **"코드 안 읽고 AI가 준 걸 Accept All(전부 수락)하며 흐름 타는 것"**이었어요. 그리고 그는 이걸 **주말 프로젝트·장난감용**이라고 했어요. 심지어 2026년 즈음엔 본인도 **"순수 바이브 코딩의 시대는 지났다"**고 말했고요.

무슨 뜻이냐면 — **진짜 사용자가 붙는 순간, 졸업이 필요**하다는 거예요. "AI 그만 쓰기"가 아니라, **AI가 뭘 하는지 알고 쓰기**로 올라가는 거예요.

이걸 한 문장으로 정리한 게 사이먼 윌리슨(Simon Willison)의 **황금률**이에요:

> **"남에게 정확히 설명하지 못하는 코드는 커밋(저장)하지 않는다."**

특히 **시크릿(비밀 키)·개인정보·유료 API(돈 나가는 것)**를 건드리는 코드는 **바이브만으로 하지 마세요.** 여기서 실수하면 돈이 새거나 남의 정보가 털려요.

### 문법을 몰라도 코드를 읽는 사다리

"난 개발자가 아닌데 코드를 어떻게 읽어요?" — 문법을 외우라는 게 아니에요. **뭘 하는지 파악**하는 거예요. 한 칸씩 올라가세요.

| 칸 | 무엇을 | 어떻게 |
|---|---|---|
| ① 요약 요청 | 이 파일이 뭐 하는지 | AI에게 "이 파일이 무슨 일을 하는지 **쉬운 말로** 요약해줘" |
| ② 구조 파악 | 폴더들이 각각 무슨 역할인지 | 코치에게 폴더 구조(`tree`)를 붙여 "각 폴더가 뭐 하는 곳인지" 물어보기. **하루 15분**이면 충분 |
| ③ 흐름 추적 | 버튼 하나 → 결과까지 | "이 버튼을 누르면 어떤 파일들이 순서대로 일하는지 따라가서 설명해줘" |
| ④ "왜"를 묻기 | 이유·의도 | "무엇"보다 **"왜 이렇게 했어?"**를 물어라. 이게 진짜 이해 |
| ⑤ diff 읽기 | 바뀐 부분 | AI가 준 변경을 **수락(Accept)하기 전에** 바뀐 줄(diff)을 읽어라 |
| ⑥ 위험신호 감지 | 문법 몰라도 되는 상식 | "맞는 데이터를 저장하나? 이 사람이 저 데이터를 볼 **권한**이 맞나? 계산이 **말이 되나?**" |

⑥번이 핵심이에요. 문법은 몰라도 **"이거 좀 이상한데?"**는 상식으로 느낄 수 있어요. 그 감각이 초보를 지켜줘요.

### 70% 벽 — AI가 절대 안 알려주는 것

애디 오스마니(Addy Osmani)가 정리한 유명한 현상이에요. **AI는 처음 70%를 놀랍도록 빠르게** 만들어줘요. 그런데 **마지막 30%가 지옥**이에요.

- 그 30%가 뭐냐면 — 에러 처리, 이상한 입력(엣지 케이스), 보안, 모니터링. **보이지 않는데 진짜 중요한 것들.**
- 실제로 **눈에 보이는 UI는 전체의 20%**밖에 안 돼요. **나머지 80%**가 그 안 보이는 것들이에요.
- **두더지잡기 루프**(하나 고치면 다른 게 깨지고, 그걸 고치면 또 딴 게 깨지는 무한 반복)에 빠졌다면 — 그게 바로 **70% 벽에 부딪힌 신호**예요.
- 비개발자는 이 벽이 **더 심해요.** 이유 둘: (1) 코드가 어떻게 얽혀 있는지 머릿속 지도(멘탈모델)가 없고, (2) AI는 **대화 세션이 바뀌면 이전에 뭘 했는지 기억을 못 해요.** 그래서 같은 실수를 반복해요.

### 개발자를 불러야 할 시점 (트립와이어)

**트립와이어(걸리면 경보가 울리는 선)** 예요. 아래 중 하나라도 걸리면, 부끄러워 말고 개발자를 부르세요.

- **새 기능 만드는 시간보다 이미 있는 걸 고치는(패치) 시간이 더 길다.**
- **두더지잡기가 며칠째 안 끝난다.**
- **진짜 사용자·민감한 개인정보·외부 서비스 연동(결제·API)**이 얽혀 있다.
- **수정하는 게 무섭다** ("건드리면 뭐가 터질지 몰라서").
- **90일 방치**하면 나중엔 고치는 것보다 처음부터 다시 짜는 게 빠른 상태가 돼요.

여기서 오해 하나 풀게요. 목표는 **"바이브 코딩 그만"이 아니에요.** 목표는 **하이브리드(섞어 쓰기)**예요:

> **프로토타입·UI 뽑기는 AI로 빠르게. 인프라·보안·성능처럼 안 보이는 30%는 개발자와 함께.**

그리고 **개발자를 뽑을 때 팁**: **"이거 다 갈아엎고 새로 짭시다"**라고 하는 사람은 오히려 **위험**해요. 당신이 만든 걸 이해하고 **살려서 확장하는** 사람이 좋은 개발자예요. (다 갈아엎으면 당신의 시간·비용이 다 날아가요.)

## 이렇게 하세요

1. **내 앱 구조부터 AI에게 요약받으세요.** (아래 프롬프트) 폴더별 역할 + 핵심 파일이 하는 일을 표로.
2. **그 설명을 문서로 저장하세요.** AI가 준 구조 설명을 README(설명서) 초안으로 남겨요. 나중에 개발자에게 넘길 때 그대로 써요.
3. **앞으로 diff를 수락 전에 읽는 습관을 들이세요.** 하루 15분, 파일 하나씩 "이게 뭐 하는지" 물어보기.
4. **트립와이어 체크리스트를 내 상황에 대입해보세요.** 걸리는 게 있으면, 아래 "핸드오프 준비"를 시작하세요.

### 핸드오프(개발자에게 넘기기) 준비

개발자를 부르기로 했다면, 아래를 준비해두면 인계가 **훨씬** 매끄러워요 (=돈·시간 절약):

- **깔끔한 Git 히스토리** — 저장점(커밋)이 꾸준히 찍혀 있으면 개발자가 흐름을 읽어요. → [[제품01-버전관리-Git-되돌리기]]
- **쉬운 말 README + 구조 요약** — 위에서 AI가 만든 설명을 문서로.
- **결정 기록** — "왜 이렇게 했는지" 메모. (예: "결제는 Toss 씀, 이유는 ~")
- **모듈화** — 기능별로 파일이 나뉘어 있으면 좋아요. (코치에게 "정리해줘" 요청 가능)
- **로컬 셋업 + env 목록** — 개발자가 자기 컴퓨터에서 앱을 켜는 법 + 필요한 환경변수 **이름 목록**. 단, **진짜 시크릿 값은 문서에 쓰지 말고**, 넘길 땐 **로테이션(키를 새로 발급해 교체)** 하세요. 절대 깃에 커밋 금지.
- **알려진 버그·미완성 30% 솔직히** — 숨기지 말고 "여기가 아직 안 됨"을 목록으로. 정직이 신뢰를 사요.

## 🤖 AI(코치)에게 줄 프롬프트

```
내 앱 전체 구조를 개발자에게 넘길 수 있게 정리해줘.

1. 폴더별로 뭐 하는 곳인지 쉬운 말로 설명해줘.
2. 각 핵심 파일이 무슨 일을 하는지 표로 정리해줘.
3. 이 앱을 다른 사람 컴퓨터에서 켜려면 뭐가 필요한지(로컬 셋업 순서 + 필요한 환경변수 이름 목록) 알려줘.
   - 단, 진짜 시크릿 값(키의 실제 문자열)은 문서에 절대 쓰지 마. 이름만.
4. 위 내용을 합쳐서, 개발자에게 넘길 수 있는 README 초안을 만들어줘.
5. 지금 알려진 버그나 미완성된 부분이 있으면 솔직하게 목록으로 적어줘.
```

## ✅ 여기까지 하면 이렇게 보여요

- 내 앱의 **폴더·핵심 파일이 각각 뭘 하는지** 표로 정리됐어요.
- 그 설명이 **README 초안(문서)**으로 저장됐어요 — 개발자에게 넘길 준비 완료.
- **트립와이어 체크리스트**로 "지금 내가 벽에 부딪혔는지"를 판단할 수 있어요.
- diff를 **수락 전에 읽는** 습관이 시작됐어요.

> 코치는 구조 요약 + README 초안이 만들어지고 트립와이어를 함께 점검한 게 확인되면 `진행상태.md`의 심화 트랙에서 이 모듈을 `- [x]`로 바꾸고 `상태.json`을 갱신합니다.

## ⚠️ 자주 하는 실수

- **"돌아간다 = 끝"으로 착각.** 보이는 UI는 20%예요. 안 보이는 80%(에러·보안·엣지케이스)가 진짜.
- **못 읽는 diff를 계속 수락.** 이해 못 한 변경을 쌓으면 결국 아무도 못 고치는 코드가 돼요.
- **무한 AI 수정(두더지잡기).** 하나 고치고 열 개 부수는 루프가 며칠째면 → 벽 신호. 개발자를 부르거나 잠깐 멈추세요.
- **RLS(남 데이터 못 보게 하는 잠금) 끄고, 키 노출한 채 출시.** 시크릿·개인정보는 바이브만으로 하지 마세요. → [[제품03-안전하게-지키기-보안-체크리스트]]
- **"전부 다시 짭시다"라는 개발자 채용.** 살려서 확장하는 사람이 좋은 개발자예요.
