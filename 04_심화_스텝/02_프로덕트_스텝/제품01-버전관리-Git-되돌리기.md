# 제품01 — 버전관리(Git)와 되돌리기 3층

## 🎯 이 스텝에서 하는 일 (한 줄)
AI가 뭔가 부쉈을 때 **한 번에 이전 상태로 되돌릴 수 있는 안전망**을 갖춥니다.

`⭐⭐ 보통 · 🕐 약 30분`

## 🔔 이 모듈이 필요한 신호
- AI에게 수정을 시킬 때마다 **"이러다 멀쩡한 걸 부수는 거 아냐?"** 하고 불안하다.
- 이미 인터넷에 올라간(라이브) 앱을 **직접 고치는 중**이다.
- **"아, 방금 그거 되돌리고 싶다"**가 자주 생긴다.

## 왜 이렇게 하나

바이브 코딩에서 사람들이 **가장 흔히 빠뜨리는 1순위**가 이거예요. 되돌리는 법을 안 배우고 시작해서, AI가 멀쩡한 걸 부쉈을 때 **손 쓸 방법이 없어 앱을 통째로 날리는** 일이 정말 많아요.

**Git(깃)**은 한 마디로 **타임머신이자 게임 세이브**예요. 게임하다 위험한 구간 앞에서 "저장" 누르고, 죽으면 그 저장 지점으로 돌아가잖아요. Git이 딱 그거예요. 잘 되는 상태에서 **"저장점(커밋)"**을 찍어두면, 나중에 AI가 뭘 부숴도 그 지점으로 **되돌릴 수 있어요.**

이게 왜 **유일한 진짜 안전망**이냐면 — AI는 "방금 한 걸 되돌려줘"라고 해도 **완벽하게 못 되돌려요.** 세션(대화)이 바뀌면 뭘 바꿨는지 기억도 못 해요. 하지만 Git 저장점은 **파일 상태를 통째로 사진 찍어둔 것**이라, 언제든 정확히 그 시점으로 갈 수 있어요.

### 되돌리기는 3층으로 되어 있어요

되돌리기 수단이 하나가 아니에요. 상황에 따라 쓰는 층이 달라요.

| 층 | 무엇 | 언제 쓰나 | 특징 |
|---|---|---|---|
| **1층. Git 커밋 / `git revert`** | 코드의 "세이브 포인트". `git revert`는 나쁜 변경을 **취소하는 새 기록**을 남김 | 커밋(저장)까지 했는데 그게 나쁠 때 | 히스토리(기록)를 지우지 않고 **안전하게** 되돌림. 진짜 안전망 |
| **2층. Vercel Instant Rollback** | 라이브(인터넷에 올라간) 앱을 **클릭 한 번**으로 이전 배포로 복구 | **나쁜 버전이 이미 라이브라 사용자가 보고 있을 때** | 재빌드(다시 만들기) 없이 **수 초** 만에 복구. Vercel 대시보드 버튼. (무료 Hobby는 직전 배포로 되돌리기) |
| **3층. 에디터 체크포인트** (Cursor 등) | 채팅 안에서 AI가 방금 편집한 걸 **임시로** 되돌림 | 아직 커밋 전, 편집하다 AI가 엉망으로 만들었을 때 | 빠르지만 **Git 커밋이 아니고, 백업 대체도 아님.** 채팅 닫으면 사라질 수 있음 |

> 핵심: **3층(체크포인트)은 임시 메모, 1층(커밋)은 진짜 저장, 2층(Instant Rollback)은 이미 터진 불 끄기.** 3층만 믿으면 안 돼요.

### 상황별로 어느 층을 쓰나

| 상황 | 이렇게 |
|---|---|
| 편집하는 중인데 AI가 방금 엉망으로 만들었다 (아직 커밋 전) | **에디터 체크포인트 복원** (3층) |
| 커밋(저장)까지 했는데 그 버전이 나쁘다 | **`git revert`** (1층) — 코치에게 "마지막 저장점으로 되돌려줘" |
| 나쁜 버전이 **이미 라이브**라 사용자가 보고 있다 | **Vercel Instant Rollback** (2층) — 대시보드에서 이전 배포로 클릭 |

### main을 직접 고치지 마세요 (브랜치 → 프리뷰 → 병합)

**main(메인)**은 **지금 인터넷에 올라가 있는 진짜 버전**이에요. 여기를 바로 고치면, 고치다 부순 게 **즉시 사용자에게 보여요.** 사고 나요.

그래서 개발자들은 이렇게 해요:

1. **브랜치(가지)** 를 하나 따요. main을 복사한 **연습장** 같은 거예요.
2. 거기서 AI랑 마음껏 고쳐요. 부숴도 main은 멀쩡해요.
3. **Vercel Preview(프리뷰) URL** — 그 브랜치만의 **미리보기 주소**가 자동으로 생겨요. 진짜 배포 전에 "이렇게 나오는구나"를 안전하게 확인할 수 있어요.
4. 프리뷰에서 멀쩡한 걸 확인하면, 그제서야 **main에 병합(합치기)** 해서 진짜로 반영해요.

이 브랜치·커밋·병합은 **코치가 대신** 해줘요. 당신은 **"저장점 찍어줘", "되돌려줘", "프리뷰로 먼저 보여줘"** 이 세 마디만 할 줄 알면 돼요.

## 이렇게 하세요

1. **지금 잘 되는 상태에 저장점을 찍으세요.** (아래 첫 프롬프트) 코치가 커밋을 남겨요.
2. **되돌리기 실험을 한 번 해보세요.** 일부러 작은 변경을 시키고 → "방금 거 되돌려줘"로 원상복구되는 걸 **눈으로** 확인. 안전망이 진짜 있는지 체감하는 게 목적이에요.
3. **Vercel Instant Rollback 버튼 위치를 지금 찾아두세요.** 불이 났을 때 소화기 위치를 찾으면 늦어요. Vercel 대시보드 → 내 프로젝트 → **Deployments(배포 목록)** → 이전 배포 옆 **점 세 개(⋯) → Instant Rollback**. 지금 클릭해보진 말고, **어디 있는지만** 눈에 익혀두세요.
4. **앞으로 새 기능은 "프리뷰로 먼저"를 습관화하세요.** (아래 세 번째 프롬프트)

## 🤖 AI(코치)에게 줄 프롬프트

**저장점 찍기:**
```
지금까지 잘 된 상태를 저장점(커밋)으로 남겨줘. 커밋 메시지는 "[무엇: 예 - 로그인 화면 완성]"으로 해줘.
남긴 다음에, 방금 뭘 저장했는지 한 줄로 알려줘.
```

**되돌리기:**
```
방금 변경으로 앱이 망가졌어. 마지막 저장점으로 되돌려줘.
- 되돌리기 전에, 어떤 방법으로 되돌릴 건지(체크포인트 / git revert) 먼저 한 줄로 알려줘.
- 되돌린 다음, 화면이 원래대로 돌아왔는지 내가 확인할 수 있게 알려줘.
```

**라이브에 바로 반영하지 말고 프리뷰로 먼저:**
```
이 변경은 라이브(main)에 바로 반영하지 마.
- 새 브랜치를 만들어서 거기서 작업하고, Vercel 프리뷰 주소를 줘.
- 내가 프리뷰에서 확인하고 괜찮다고 하면, 그때 main에 합쳐줘.
- 시크릿(API 키 등)은 코드에 넣지 말고 그대로 환경변수에 둬.
```

## ✅ 여기까지 하면 이렇게 보여요

- 잘 되는 상태에 **저장점(커밋)**이 남아 있어요.
- 일부러 부순 걸 **되돌려서 원상복구**되는 걸 눈으로 봤어요. → 안전망이 진짜 있다는 걸 체감.
- **Vercel Instant Rollback 버튼 위치**를 알아요 (불나기 전에).
- 앞으로 큰 변경은 **프리뷰 주소로 먼저 확인**하는 습관이 잡혔어요.

> 코치는 저장점·되돌리기·프리뷰 흐름을 한 번씩 해본 게 확인되면 `진행상태.md`의 심화 트랙에서 이 모듈을 `- [x]`로 바꾸고 `상태.json`을 갱신합니다.

## ⚠️ 자주 하는 실수

- **커밋 없이 몇 시간을 몰아서 작업.** 그러다 부수면 **되돌릴 지점이 없어요.** 잘 될 때마다 자주 저장점을 찍으세요("작게 자주").
- **라이브(main)를 직접 편집.** 부순 게 즉시 사용자에게 보여요. 큰 변경은 브랜치 → 프리뷰 → 병합.
- **되돌리기 수단 위치를 몰라 우왕좌왕.** 특히 Vercel Instant Rollback 버튼은 **미리** 찾아두세요.
- **에디터 체크포인트를 백업이라 착각.** 그건 임시 메모예요. 진짜 안전망은 **Git 커밋(1층)**.
