# 제품03 — 안전하게 지키기 (보안 체크리스트)

## 🎯 이 스텝에서 하는 일 (한 줄)
진짜 사용자에게 공개하기 **전에**, 새는 곳이 없는지 보안 체크리스트를 한 번에 훑습니다.

`⭐⭐⭐ 어려움 · 🕐 약 40분`

## 🔔 이 모듈이 필요한 신호
- 곧 **진짜 사람들에게 공개**하려 한다 (친구 몇 명 넘어서).
- 이메일·이름·사진 같은 **개인정보를 받는다.**
- "**해킹·유출이 무섭다.**" 뉴스에서 유출 사고를 보고 남 일 같지 않다.

## 왜 이렇게 하나 (겁주려는 게 아니라, 현실이라서)

솔직하게 말할게요. **AI가 짠 코드는 기본적으로 안전하지 않을 때가 많아요.**

- AI에게 "안전하게 vs 취약하게" 고를 수 있는 상황을 주면, **45%가 취약한 쪽을 골라요**(Veracode 조사). AI는 "돌아가는 코드"를 목표로 하지 "안전한 코드"를 목표로 하지 않거든요.
- 바이브 코딩으로 만든 앱을 조사했더니 **5개 중 1개**에 시스템적 위험이 있었고(Wiz), 앱 **1,072개를 스캔하니 98%에 결함**이 있었어요(Symbiotic).
- 실제 사고: **Tea 앱**은 사용자 **신분증 사진 포함 7.2만 장**이 유출됐어요. 원인은 "경로가 복잡하니까 아무도 못 찾겠지"라는 방심이었어요. 하지만 공격자는 경로를 찾아냅니다.

즉, **Accept All(AI가 준 걸 다 수락)만으론 부족한 지점**이 바로 여기예요. 이 스텝은 당신이 직접 눈으로 확인하는 체크리스트예요.

## 이렇게 하세요 (필수 체크리스트)

### (a) 시크릿은 env에만 — `NEXT_PUBLIC_` 함정을 조심

Next.js에는 함정이 하나 있어요. **`NEXT_PUBLIC_`으로 시작하는 환경변수는 브라우저에 그대로 박혀요.** 누구나 개발자도구(F12)로 읽을 수 있어요 — 이건 버그가 아니라 "공개용"이라는 뜻이라 그래요.

그래서 **진짜 시크릿에는 절대 `NEXT_PUBLIC_`을 붙이면 안 돼요:**

| 붙여도 되는 것 | **절대 안 되는 것 (진짜 시크릿)** |
|---|---|
| Supabase anon 키, 공개 사이트 주소 | Supabase **`service_role`** 키 |
| 공개용 설정값 | Stripe **`sk_live_`** 같은 비밀 키 |
| | 각종 **API 키** (OpenAI·Claude·결제 등) |

- **"클라에서 undefined가 뜬다"고 `NEXT_PUBLIC_`을 붙이지 마세요.** 그건 "이 코드를 브라우저에서 돌리면 안 된다"는 신호예요. **그 코드를 서버로 옮겨야** 해요(코치에게 "이 키 쓰는 부분을 서버로 옮겨줘"라고 시키세요).
- `.env` 파일은 반드시 `.gitignore`에 넣어 깃에 안 올라가게 하세요(코치가 챙기지만 확인하세요).
- **직접 확인:** 배포된 사이트에서 F12 → 소스/네트워크에서 `sk_live_`, `service_role`을 검색해 **안 나오는지** 눈으로 보세요. 나오면 새고 있는 거예요.

### (b) RLS — 배포 전 모든 테이블 초록불

사용자 데이터가 있으면 **모든 테이블 RLS가 켜져** 있어야 해요. 자세한 건 [[제품02-진짜-로그인과-회원-Auth와-RLS]]에 있어요. (이거 안 하면 위 (a)를 다 지켜도 데이터가 통째로 공개돼요.)

### (c) 클라이언트 입력을 믿지 마세요

**가격·권한·수량 같은 중요한 값은 서버에서 다시 검증**해야 해요. 브라우저에서 온 값은 조작될 수 있거든요.

- 나쁜 예: 결제 금액을 화면에서 받은 그대로 처리 → 공격자가 100원으로 바꿔 보냄.
- 나쁜 예: `localStorage`에 `{authenticated: true}` 같은 플래그를 두고 그걸로 관리자 판단 → 누구나 그 값을 켜서 관리자가 됨.
- 원칙: **"돈·권한·수량"은 서버가 진실의 원천.** 화면 값은 참고일 뿐이에요.

### (d) 레이트 리밋(요청 횟수 제한)을 거세요

**레이트 리밋**은 "한 사람이 1분에 몇 번까지만 요청 가능"으로 막는 거예요. 없으면 악성 스크립트나 버그 하나가 **서버를 마비**시키거나, 유료 API를 무한 호출해 **요금 폭탄**을 낼 수 있어요.

- 쉬운 방법: **Upstash Redis + `@upstash/ratelimit`**(무료 티어, 세팅 약 10분). 코치에게 붙여달라고 하세요.
- 특히 **로그인·회원가입·AI 호출·글쓰기 API**에 꼭 거세요(이게 가장 자주 남용되는 곳).

### (e) 검증된 인증만 쓰고, 열린 관리자 페이지를 없애세요

- 로그인은 직접 만들지 말고 **Supabase Auth 같은 검증된 것**을 쓰세요([[제품02-진짜-로그인과-회원-Auth와-RLS]]).
- **관리자 페이지·스테이징(테스트) 페이지를 로그인 없이 공개하지 마세요.** `/admin` 같은 주소는 누구나 주소만 알면 들어와요. 반드시 인증으로 막으세요.

## 한국 개인정보(PIPA) — 이건 법적 의무예요

개인정보(이메일·이름·사진 등)를 **받는 순간**, 한국에선 지켜야 할 법이 생겨요. 몰라서 안 하면 과태료를 물어요.

- **개인정보처리방침 작성·공개는 법적 의무예요**(개인정보보호법 30조). **안 하면 1천만원 이하 과태료.**
- **무료로 만드는 법:** 정부 **개인정보 포털(privacy.go.kr) → 개인정보 도우미 → 개인정보처리방침 만들기.** 질문에 답하면 문서를 만들어줘요. 그 문서를 사이트 하단에 링크로 걸면 돼요.
- **이용약관**은 공정거래위원회 표준양식을 참고하면 돼요.
- 소규모 인디 앱은 CPO(개인정보 보호책임자) 신고·별도 등록까지는 **대체로 불필요**하지만, **처리방침 공개**와 **유출 시 72시간 이내 통지**는 **규모와 무관하게 의무**예요.
- **가장 중요한 원칙: 필요한 최소한만 수집하세요.** 안 받은 정보는 샐 일도 없어요. "혹시 몰라서" 전화번호·주소를 받지 마세요.

## 🤖 AI(코치)에게 자기 코드 보안 점검시키기

Claude Code를 쓴다면 **`/security-review`** 명령을 쓸 수 있어요 — 대기 중인 변경을 의미 기반으로 분석해 OWASP(대표적인 웹 취약점 목록) 문제와 수정법을 짚어줘요. 그게 없어도 아래 프롬프트를 복붙해 점검시킬 수 있어요.

```
① 이 코드의 OWASP Top 10 취약점을 찾아줘. 취약한 라인, 왜 위험한지, 고친 코드를 각각 줘.

② 프로젝트 전체(.env 처리와 git 히스토리 포함)에서 하드코딩된 시크릿과,
   NEXT_PUBLIC_ 으로 브라우저에 새고 있는 값이 있는지 스캔해줘.

③ 내 Supabase 모든 테이블의 RLS 상태를 점검하고, 로그인한 유저가 남의 행을
   읽거나 지울 수 있는지 확인해줘. 뚫려 있으면 본인만 접근하는 정책을 새로 짜줘.

④ 이 앱에서 인증·가격·권한을 판단할 때 클라이언트(브라우저) 입력을 그대로 믿는
   곳을 찾아줘. 서버에 빠진 검증이 어디인지 알려줘.
```

> ⚠️ **주의:** AI에게 "고쳐" → "또 고쳐"를 반복시키면 보안이 **오히려 나빠질 수 있어요**(AI가 이전 안전장치를 지워버리기도 해요). 큰 수정을 할 때마다 위 점검을 **다시 돌려** 확인하세요.

## ✅ 여기까지 하면 이렇게 보여요

- 배포된 사이트 개발자도구(F12)에서 `sk_live_`·`service_role` 같은 **시크릿이 안 나와요.**
- Supabase에서 **모든 테이블 RLS 초록불**이에요.
- 개인정보를 받는다면 사이트 하단에 **개인정보처리방침 링크가 공개**돼 있어요.
- 로그인·AI 호출 같은 곳에 **레이트 리밋**이 걸려 있어요.
- **안 되면:** 점검 프롬프트 결과에 겁먹지 마세요. 하나씩 코치와 고치면 돼요. → [[스텝08-막혔을때-에러-읽고-디버깅]]

> 코치는 이 체크리스트가 실제로 통과됐는지(특히 devtools에 시크릿 없음 + 모든 테이블 RLS 초록불) 확인한 뒤에만 `진행상태.md`의 이 줄을 `- [x]`로 바꾸고 `상태.json`을 갱신합니다.

## ⚠️ 자주 하는 실수

- **진짜 시크릿에 `NEXT_PUBLIC_`을 붙이기.** 브라우저에 그대로 노출돼요. 서버로 옮기세요.
- **`.env`를 깃에 커밋하기.** 한 번 올라가면 히스토리에 영영 남아요. `.gitignore` 확인.
- **RLS를 끈 채 출시.** 데이터 통째로 공개. [[제품02-진짜-로그인과-회원-Auth와-RLS]] 먼저.
- **클라이언트 입력을 믿기.** 가격·권한·수량은 서버에서 재검증.
- **처리방침 없이 개인정보 수집.** 1천만원 이하 과태료 대상이에요. privacy.go.kr에서 무료로 만드세요.
