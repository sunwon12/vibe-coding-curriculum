# 스텝05 — 첫 화면 바로 뽑기 (첫 승리 🎉)

## 🎯 이 스텝에서 하는 일
지금까지 글로 정한 걸 실제 화면으로 뽑아서, **브라우저에서 처음으로 "내 앱"을 눈으로 봅니다.**

`⭐⭐ 보통 · 🕐 약 30분`

## 왜 이렇게 하나

여기가 이 커리큘럼의 **첫 승리 🎉**예요. 지금까지는 아이디어·PRD·화면 스케치처럼 **글**만 만들었죠. 이번엔 그 글을 근거로 **진짜 화면**을 뽑습니다.

바이브 코딩의 큰 원칙 하나가 **"기획을 오래 끌지 말고, 바로 페이지를 뽑는다"**예요. 완벽한 설계도를 다 그린 뒤에 짓는 게 아니라, **일단 눈에 보이는 걸 하나 세우고** 거기서부터 고쳐 나가는 방식이에요. 화면이 눈앞에 뜨는 순간, "아, 내가 뭘 만들고 있구나"가 몸으로 느껴지고 자신감이 붙습니다.

집에 비유하면, 지금은 **모델하우스의 거실 하나**를 먼저 세우는 거예요. 부엌·화장실·전기·수도(저장 기능·로그인)는 아직 없어요. 벽과 소파만 있는 빈 방이죠. 그래도 **문 열고 들어가 볼 수 있는 진짜 공간**이라는 게 중요해요.

그리고 안심하세요. **뼈대를 세우는 일(설치·실행)은 전부 코치가 대신** 합니다. Next.js니 Tailwind니 하는 **스택 이름은 몰라도 돼요.** 당신은 "이 화면 만들어줘"라고 부탁하고, 브라우저에서 열어서 확인만 하면 됩니다.

## 이렇게 하세요

1. **AI 채팅창을 새 대화로 여세요.**
   - 앱 폴더에서 Codex CLI나 Claude Code를 실행합니다. 이전 대화가 길면 새 대화로 시작하는 게 깔끔해요.

2. **코치에게 "화면정의.md 기반으로 메인 화면을 만들어달라"고 부탁하세요.** (아래 프롬프트 복붙)
   - 코치가 먼저 `02_템플릿/화면정의.md`와 PRD를 읽고, **프로젝트 뼈대(설치)** 를 세운 뒤 **메인 화면 하나**를 만들어 줍니다.
   - 이 과정에서 코치가 "지금 설치하는 중이에요", "화면 만드는 중이에요"라고 알려줄 거예요. 시간이 조금 걸려도 정상이에요.

3. **코치가 "개발 서버를 켰어요"라고 하면, 알려주는 주소를 브라우저에서 여세요.**
   - 보통 `http://localhost:3000` 같은 주소예요.
   - **localhost(로컬호스트)** = "내 컴퓨터에서만 열리는 미리보기 주소"예요. 아직 인터넷에 올라간 게 아니라, 나만 볼 수 있는 연습 무대예요. (진짜 인터넷 공개는 스텝11에서 해요.)
   - 주소를 어디에 어떻게 붙여넣는지 모르면, 코치에게 "이 주소 브라우저에서 어떻게 여는지 알려줘"라고 물으세요.

4. **화면이 떴으면, 내가 정의한 대로 나왔는지 눈으로 확인하세요.**
   - 제목·목록·입력칸 같은 게 화면정의.md에서 정한 모습과 비슷하면 성공이에요.
   - 아직 버튼을 눌러도 저장은 안 돼요. **그게 정상이에요** (저장은 스텝08에서).

## 🤖 AI(코치)에게 줄 프롬프트

새로 만드는 요청이라 **4가지 재료**(무엇인지 · 누구용 · 무슨 기능 · 어떻게 생겼는지)를 채워서 줍니다. 대괄호 `[ ]` 안을 내 프로젝트로 바꾸세요.

```
02_템플릿/화면정의.md와 PRD.md를 읽고, 거기 정의된 메인 화면을 실제로 만들어줘.

- 이건 [무엇인지: 예 "내가 읽은 책을 기록하는 웹앱"]이야.
- [누구용: 예 "혼자 쓰는 독서 기록용, 나만 봄"].
- 메인 화면에는 [무슨 기능: 예 "책 목록이 보이고, 위에 '제목·별점' 입력칸과 추가 버튼이 있음"].
- 분위기는 [어떻게 생겼는지: 예 "노션처럼 차분하고 깔끔하게, 흰 바탕에 군더더기 없이"].

설치랑 실행(개발 서버 켜기)은 네가 대신 해주고, 다 되면
브라우저에서 어떤 주소로 어떻게 여는지 알려줘.
지금은 로그인이랑 데이터 저장(DB)은 아직 붙이지 마. 화면만 먼저 보고 싶어.
```

## ✅ 여기까지 하면 이렇게 보여요

- 브라우저 주소창에 `localhost` 주소를 넣으면, **내가 정의한 화면**(제목·목록·입력칸 등)이 뜹니다.
- 버튼을 눌러도 아직 저장은 안 되고, 로그인 창도 없어요 — **전부 정상**이에요. 지금은 "보이는 화면"까지가 목표예요.
- **안 뜨거나 빨간 글씨(에러)가 나오면:** 겁먹지 말고 그 화면·에러 글씨를 **전문 그대로 복사**해서 코치에게 붙여넣으세요. 에러는 실패가 아니라 단서예요. → [[스텝09-막혔을때-에러-읽고-디버깅]]

> 코치가 이 화면을 눈으로 확인(스크린샷이나 "떴어요" 확인)하면, `진행상태.md`의 이 줄을 `- [x]`로 바꾸고 `상태.json`을 갱신해 줍니다.

## ⚠️ 자주 하는 실수

- **한 번에 앱 전체를 만들려는 것.** "목록도 저장도 로그인도 다 만들어줘"라고 하면 뭐가 깨졌는지 못 찾아요. 지금은 **메인 화면 하나만.**
- **안 예쁘다고 좌절하기.** 첫 화면은 원래 투박해요. **다듬기(디자인)는 스텝10**에서 따로 해요. 지금은 "떴다"가 성공이에요.
- **에러가 뜨면 창을 닫아 버리기.** 에러는 정상이고, 붙여넣으면 같이 고쳐요. 닫지 마세요.
- **localhost 주소를 인터넷 공개 주소로 착각하기.** 이건 내 컴퓨터에서만 보이는 미리보기예요. 남에게 링크로 보내는 건 스텝11입니다.
