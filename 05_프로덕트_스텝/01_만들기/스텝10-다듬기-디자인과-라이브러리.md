# 스텝10 — 다듬기: 디자인과 라이브러리

## 🎯 이 스텝에서 하는 일
잘 돌아가는 앱을 이제 **보기 좋고 쓰기 편하게** 정돈하고, 모바일에서도 안 깨지는지 확인합니다.

`⭐⭐ 보통 · 🕐 약 30분`

## 왜 이렇게 하나

여기까지 앱은 **돌아가긴** 하지만 아마 좀 투박할 거예요. 그건 정상이에요 — 먼저 돌아가게 만들고, 그다음에 다듬는 게 순서니까요. 이제 다듬을 차례입니다.

**AI 디자인은 "근거 있는 단순한 한 마디"에 잘 반응해요.** "예쁘게 해줘"는 너무 막연해서 결과가 매번 다르게 나와요. 대신 방향이 분명한 한 마디를 주면 훨씬 안정적으로 예뻐집니다.

| 막연한 말 (약함) | 근거 있는 단순 말 (강함) |
|---|---|
| "예쁘게 해줘" | "블랙 & 화이트로 정리해줘" |
| "세련되게" | "노션처럼 차분하고 여백 넉넉하게" |
| "요즘 느낌으로" | "글자 크게, 색은 회색 톤 하나로 통일" |

그리고 **좋은 라이브러리는 "설치가 곧 완성"이에요.** 우리가 쓰는 shadcn/ui는 버튼·카드·입력창처럼 **미리 잘 만들어진 UI 조각(컴포넌트)** 모음이에요. 이걸 갖다 쓰면 당신이 디자인을 몰라도 이미 프로가 다듬어 둔 모양이 나옵니다. 투박한 부분을 이 조각으로 바꾸기만 하면 돼요.

마지막으로, 다 만들었으면 **"이걸 실제로 쓸 사람" 입장에서 다시 봅니다.** 만든 사람은 어디를 눌러야 하는지 다 알지만, 처음 온 사람은 헷갈려요. 그 헷갈릴 지점을 미리 찾아 고치는 게 진짜 실력입니다.

## 이렇게 하세요

1. **전체 톤을 한 마디로 정하세요.**
   - 위 표를 참고해 딱 한 방향만 고릅니다. 예: "블랙 & 화이트", "노션처럼 차분하게", "여백 넉넉히".
   - 여러 개 섞지 말고 **하나로.** 방향이 하나여야 화면이 통일돼요.

2. **코치에게 다듬기를 부탁하세요 — 한 번에 한 부분만.**
   - 전체를 한꺼번에 갈아엎지 말고, "먼저 이 화면(또는 이 목록 부분)부터"라고 범위를 좁혀 시킵니다.
   - 여기서 중요한 안전선: **기능은 건드리지 말고 "보기랑 여백"만** 바꾸게 하세요.

3. **투박한 부분을 shadcn 컴포넌트로 바꿉니다.**
   - 밋밋한 버튼·입력창·목록 카드 같은 걸 코치가 미리 만들어진 조각으로 교체해줘요.
   - 코치가 "지금 shadcn 버튼 컴포넌트로 바꾸는 중이에요"처럼 알려줄 거예요. 조각 이름은 몰라도 됩니다.

4. **폰으로 확인하세요 (반응형 = 화면 크기에 맞춰 자동으로 정돈되는 것).**
   - 코치에게 "모바일에서 어떻게 보이는지 보여줘"라고 하면, 브라우저의 **개발자도구(모바일 미리보기 기능)**로 폰 화면을 흉내 내 보여줄 수 있어요.
   - 가능하면 **실제 폰**으로도 열어보세요(배포는 다음 스텝이지만, 개발자도구만으로도 감은 잡혀요).

5. **"처음 쓰는 사람이 헷갈릴 곳"을 점검하세요.**
   - 코치에게 실사용자 입장에서 헷갈릴 지점 3개만 짚어달라고 하고, 그중 진짜 문제만 고칩니다.

## 🤖 AI(코치)에게 줄 프롬프트

**① 톤 정돈 (편집 — 위치+행동+가드레일):**

```
지금 앱 전체를 [분위기: 예 - 블랙 & 화이트 / 노션처럼 차분하게 / 여백 넉넉히]로 정돈해줘.
한 번에 전부 말고 [이 부분: 예 - 메인 목록 화면]부터 시작해줘.

- 기능은 그대로 두고, 보기(색·글자·간격)랑 여백만 바꿔줘.
- 투박한 버튼·입력창·목록은 shadcn/ui 컴포넌트로 바꿔줘.
- 모바일에서도 안 깨지게(반응형) 해줘.
- 뭘 바꾸는 중인지 한 줄로 알려주고, 다 되면 어디를 확인하면 되는지 말해줘.
```

**② 실사용자 눈으로 점검:**

```
이 앱을 [실제 쓸 사람: 예 - 나처럼 처음 방문한 사람]이 처음 연다고 생각하고,
헷갈릴 만한 곳 3개만 짚어줘. 각각 왜 헷갈리는지랑, 어떻게 고치면 좋을지 짧게.
아직 고치지는 말고, 3개만 먼저 말해줘.
```

## ✅ 여기까지 하면 이렇게 보여요

- 화면이 한결 **정돈돼 보이고**, 폰(개발자도구 미리보기)에서도 글자·버튼이 안 깨지고 잘 보입니다.
- **기능은 그대로** 동작해요 — 저장·목록·로그인이 아까처럼 됩니다.
- **잘 안 되면:** 한 부분씩만 다시 시키세요. "방금 바꾼 것 때문에 기능이 이상해졌다" 싶으면 코치에게 그대로 말하고, 빨간 글씨(에러)가 뜨면 그대로 복사해 붙여넣으면 됩니다.

> 코치는 이 스텝이 끝난 걸 눈으로 확인(정돈된 화면 + 모바일 확인)하면 `진행상태.md`의 이 줄을 `- [x]`로 바꾸고 `상태.json`을 갱신해 줍니다.

## ⚠️ 자주 하는 실수

- **디자인하면서 기능까지 건드리는 것.** "보기만 바꿔줘"라고 분리하세요. 디자인과 기능을 한 번에 손대면 뭐가 깨졌는지 못 찾아요.
- **한 번에 전체를 갈아엎기.** 한 화면·한 부분씩. 그래야 이상해져도 어디를 되돌릴지 압니다.
- **폰 확인을 생략하는 것.** 사람들은 대부분 폰으로 열어요. PC에서만 예쁘고 폰에서 깨지면 안 쓴 것과 같아요.
- **방향을 여러 개 섞는 것.** "노션처럼 + 화려하게 + 알록달록"은 서로 싸워요. 딱 한 방향만.
