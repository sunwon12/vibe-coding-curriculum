# 제품07 — 검색과 공유로 키우기

## 🎯 이 스텝에서 하는 일 (한 줄)
"만들었는데 아무도 안 오는" 문제를 풉니다. **검색에 뜨게** 하고, **사람을 데려오는** 최소 세팅과 실전 전략을 챙겨요.

`⭐⭐ 보통 · 🕐 약 40분`

## 🔔 이 모듈이 필요한 신호
- 앱을 만들어 배포했는데 **아무도 안 온다.**
- 구글·네이버에 **내 앱을 검색해도 안 뜬다.**
- **사람을 모으고 싶은데** 어디서 어떻게 시작할지 모르겠다.

## 왜 이렇게 하나 (먼저 솔직하게)

여기서 초보가 가장 많이 하는 착각이 하나 있어요. **"SEO만 잘하면 사람이 몰려올 거야."** 아니에요. 초기엔 SEO가 **거의 안 통해요**(새 사이트는 검색 순위가 낮아서 노출까지 몇 주~몇 달 걸려요).

진짜 바늘을 움직이는 건 **분배(distribution) — 즉 "사람들이 있는 곳에 내 걸 가져가는 것"**이에요. 완벽한 제품보다 **잘 터진 런칭 글 하나**가 초기엔 훨씬 세요. 그래서 이 스텝의 전략은 이래요:

> **SEO는 30분만 세팅해 두고, 에너지는 런칭·빌드인퍼블릭·유저와의 대화에 쓴다.**

SEO는 "해두면 나중에 복리로 도움 되는 밑작업"이지, "지금 사람을 데려오는 수단"이 아니에요. 그러니 30분만 딱 세팅하고 넘어가요.

## 이렇게 하세요

### (1) 초급 SEO — 3개 파일 + 등록 (딱 30분)

Next.js에선 파일 3개면 검색 기초가 끝나요:

| 무엇 | 하는 일 |
|---|---|
| `app/sitemap.ts` | 내 페이지 목록을 **검색봇에게 지도로** 넘겨줌 |
| `app/robots.ts` | 크롤 규칙(어디를 봐도 되는지) + **사이트맵 위치**를 알려줌 |
| `layout.tsx`의 `metadata` | **검색 결과에 뜨는 제목·설명**. (미리보기 카드 OG는 [[제품06-내-도메인과-브랜딩]]) |

짧은 예시:

```ts
// app/sitemap.ts
import type { MetadataRoute } from 'next'
export default function sitemap(): MetadataRoute.Sitemap {
  return [
    { url: 'https://myapp.com', lastModified: new Date() },
    { url: 'https://myapp.com/about', lastModified: new Date() },
  ]
}
```

```ts
// app/robots.ts
import type { MetadataRoute } from 'next'
export default function robots(): MetadataRoute.Robots {
  return {
    rules: { userAgent: '*', allow: '/' },
    sitemap: 'https://myapp.com/sitemap.xml',
  }
}
```

배포한 뒤 브라우저로 **`내도메인/sitemap.xml`** 과 **`내도메인/robots.txt`** 를 직접 열어 내용이 뜨는지 확인하세요. 떠야 다음 단계(등록)를 할 수 있어요.

### (2) 검색엔진에 등록 — 구글 + ★네이버

만들어 두는 것만으론 부족해요. 검색엔진에 "여기 내 사이트 있어요" 하고 **직접 등록**해야 빨라요.

- **구글 서치콘솔:** 소유 확인(meta 태그를 layout에 넣기) → **Sitemaps** 메뉴에 `sitemap.xml` 제출 → 중요한 페이지는 **URL 검사**로 색인 요청.
- **★ 네이버 서치어드바이저 (한국이면 필수):** 한국인 상당수가 **네이버로 검색**해요. 이걸 안 하면 **국내 유입을 통째로 놓쳐요.**
  - `searchadvisor.naver.com` → 사이트 등록 → **`naver-site-verification` meta 태그**로 소유 확인. ⚠️ **HTML 태그 방식은 1년마다 재인증**이 필요해요(만료되면 연결이 끊겨요).
  - 사이트맵 제출 → **웹페이지 수집 요청.**
  - 실제 검색에 **노출되기까지 약 2주** 걸려요. 바로 안 떠도 정상이에요.

### (3) 애널리틱스 — 지금은 이거 하나만

방문자가 얼마나 오는지 안 보이면 개선할 수가 없어요. 하지만 처음부터 복잡한 걸 깔 필요는 없어요:

| 도구 | 특징 | 쿠키 동의 배너 |
|---|---|---|
| **Vercel Web Analytics** | **제일 쉬움(5분).** 이미 Vercel을 쓰니 켜기만 하면 됨 | **불필요** |
| GA4(구글 애널리틱스) | 상세·퍼널 분석까지 | **EU 사용자 대상이면 쿠키 동의 배너 필요** |
| Plausible | 쿠키 없음(프라이버시 친화) | 불필요. 단 **유료/셀프호스트** |

→ **지금은 Vercel Web Analytics만 켜세요.** 5분이면 되고 쿠키 배너도 필요 없어요. 더 정교한 분석은 사람이 실제로 오기 시작한 뒤에 붙여도 늦지 않아요.

### (4) 어디에 알릴까 — 한국 채널 + 글로벌

**여기가 초기 유입의 90%예요.** 사람들이 이미 모여 있는 곳에 내 걸 가져가세요.

한국 채널:

| 채널 | 어떻게 |
|---|---|
| **긱뉴스 (news.hada.io) Show 섹션** | 한국판 해커뉴스. **링크 + 한국어 요약**을 올리면 업보트로 노출돼요. 개발·메이커 관심층이 많아요 |
| **오픈카톡** | 관련 주제 방에 **먼저 기여(질문 답변 등)한 뒤** 공유. **홍보만 하면 강퇴**당해요 |
| **커리어리** | "사이드 프로젝트 만든 이야기 + 배운 점" 형식이 잘 먹혀요 |
| **디스콰이엇** | 한국판 Product Hunt. ⚠️ 2026-07 기준 **운영사 인수·법인 변경**이 있어 장기 안정성은 지켜봐야 해요. **여기만 올인하지 말고 병행**하세요 |

글로벌 채널:
- **Product Hunt**: 런칭 데이. 게시는 **PST(미 태평양시) 00:01**에 맞춰요(그날 하루 노출 극대화).
- **Reddit r/SideProject**: **홍보 톤 금지.** "만들었어요, 피드백 주세요" 톤으로.
- **Hacker News Show HN**: 직접 만든 걸 보여주는 섹션.

### (5) 런칭 글 실전 (이게 가장 크게 터져요)

- **제목 공식:** "서비스명 — 누구의 어떤 문제를 어떻게 해결". (막연한 자랑 X, 문제·대상이 보이게)
- **첫 댓글이 핵심이에요.** 본문보다 첫 댓글에 **왜 만들었는지 스토리 → 어떻게 해결하는지 → 피드백 요청**을 담으세요. 사람들은 스토리에 반응해요.
- **스크린샷 3~5장** 또는 **15초 데모 영상.** 글보다 눈으로 보여주는 게 강해요.
- **"업보트 해주세요"는 규정 위반**이에요(계정 제재당해요). 대신 **"써보고 솔직하게 말해달라"**고 하세요.
- **댓글에 즉시 응답**하세요. 런칭 당일 반응 속도가 순위를 좌우해요.

### (6) 빌드 인 퍼블릭 — 만드는 과정을 공개하기

완성된 걸 "짠" 하고 던지는 것보다, **만드는 과정을 공개**하는 게 훨씬 강해요. 이유:

- **책임감**(공개했으니 끝까지 하게 됨) + **오디언스 선축적**(런칭 전에 지지자를 모아둠) + **피드백 루프**(초기에 방향 교정) + **신뢰**(과정을 본 사람이 더 믿어요).

무엇을 공유하나: 진행 상황 / **지표(솔직하게)** / 스크린샷 / **실패담**. 특히 **실패담이 공감·신뢰를 가장 크게** 올려요(성공 자랑만 하면 오히려 멀어져요).

채널: **X(트위터) 스레드 `#buildinpublic`**(핵심은 **상호성** — 남의 프로젝트를 먼저 도와주면 내 차례에 도와줘요), 스레드(Threads), **디스콰이엇 메이커로그**, 블로그(느리지만 SEO로 복리 효과).

### (7) 얼리 유저 확보

| 방법 | 요령 |
|---|---|
| **대기자 랜딩 페이지** | 폼은 **이메일만** 받으세요. 전화·직함까지 요구하면 **가입률이 급락**해요. (평균 전환율 약 2%) |
| **가치 + 소프트 마감** | "런칭 때 25% 할인" 같은 가벼운 이유를 주면 지금 가입해요 |
| **첫 유저 무료 → 후기** | 무료로 써준 사람의 후기를 **사회적 증거**로 활용 |
| **문제 당사자에게 DM** | **팔지 말고** "이 문제 겪으시죠? 한번 봐주실래요?" — 부탁이 아니라 도움 요청 톤으로 |

당신 앱은 이미 **Next.js + Supabase**니까, **이메일만 받는 폼 + Supabase 테이블**은 **30분이면** 붙여요. 코치에게 시키면 돼요.

## 🤖 AI(코치)에게 줄 프롬프트

SEO 3파일 + 메타:
```
이 Next.js 앱에 SEO 기초를 붙여줘.
- app/sitemap.ts 와 app/robots.ts 를 만들어줘. 도메인은 [myapp.com].
- layout 의 metadata 에 검색 결과용 제목·설명을 넣어줘.
- 배포한 뒤 브라우저로 확인할 주소(sitemap.xml, robots.txt)도 알려줘.
- 구글 서치콘솔·네이버 서치어드바이저 소유확인 meta 태그는 어디에 넣는지도 알려줘.
```

애널리틱스:
```
Vercel Web Analytics 를 켜줘. 방문자 수를 보고 싶어.
쿠키 배너 없이 되는 걸로 하고, 켠 다음 어디서 숫자를 확인하는지 알려줘.
```

대기자 명단:
```
대기자 명단(waitlist)을 랜딩에 붙여줘.
- 폼은 이메일 하나만 받아줘 (전화·직함은 받지 마 — 가입률 떨어지니까).
- 입력된 이메일은 Supabase 테이블에 저장해줘.
- 제출하면 "등록됐어요" 메시지가 뜨게 해줘.
```

## ✅ 여기까지 하면 이렇게 보여요

- 브라우저로 **`내도메인/sitemap.xml`·`/robots.txt`** 가 열려요.
- 구글 서치콘솔·**네이버 서치어드바이저**에 사이트가 **등록**되고 사이트맵을 제출했어요(노출은 몇 주 뒤).
- **Vercel Web Analytics**에 방문자 숫자가 잡혀요.
- (원하면) **이메일만 받는 대기자 폼**이 랜딩에 붙어 Supabase에 저장돼요.
- 그리고 **어디에 어떻게 런칭 글을 올릴지** 계획이 섰어요.
- **안 되면:** 검색에 바로 안 떠도 정상이에요(노출까지 시간이 걸려요). 지금은 사람에게 직접 알리는 데 집중하세요. 에러는 코치에게 전문 붙이기. → [[스텝09-막혔을때-에러-읽고-디버깅]]

> 코치는 sitemap/robots가 실제로 열리고 네이버·구글 등록 및 애널리틱스가 켜진 걸 확인한 뒤에만 `진행상태.md`의 이 줄을 `- [x]`로 바꾸고 `상태.json`을 갱신합니다.

## ⚠️ 자주 하는 실수

- **SEO에 매몰되기.** 초기엔 SEO가 거의 안 통해요. **사람에게 직접 알리는 게 먼저.** SEO는 30분만.
- **커뮤니티에 홍보 톤만 던지기.** 오픈카톡·Reddit·긱뉴스는 **먼저 기여하고** 공유하는 곳이에요. 광고만 하면 강퇴·차단.
- **네이버 등록을 빼먹기.** 한국인 상당수가 네이버로 검색해요. 안 하면 **국내 유입을 통째로 손실**해요.
- **대기자 폼에 전화·직함까지 요구하기.** 가입률이 급락해요. **이메일만.**
- **"업보트 해달라"고 하기.** 규정 위반이에요. "솔직한 피드백 달라"로.
