# 제품08 — 비용·성능·모바일

## 🎯 이 스텝에서 하는 일 (한 줄)
**요금 폭탄과 앱 멈춤을 막고**, 느려진 앱을 손보고, "앱스토어에 올리고 싶다"에 대한 **현실적인 답**을 정합니다.

`⭐⭐ 보통 · 🕐 약 35분`

## 🔔 이 모듈이 필요한 신호
- **갑자기 앱이 멈추거나 느려진다.**
- **요금 폭탄**이 무섭다 (모르는 새 큰 청구가 올까 봐).
- **"앱스토어에 올리고 싶다"**는 생각이 든다.

## 왜 이렇게 하나

이제 진짜 사용자가 붙기 시작하면 **돈과 속도**가 걸려요. 다행히 대부분의 위험은 **미리 스위치 하나만 켜두면** 막을 수 있어요. 문제는 그 스위치가 **기본으로 꺼져 있다**는 거예요. 이 모듈은 그 스위치들을 켭니다.

> 💡 **"돌아간다"와 "많이 써도 버틴다"는 달라요 — 스케일 절벽.** 프로덕션 가이드들이 자주 쓰는 표현이 있어요:
> **"50명이면 괜찮고, 5,000명이면 위태롭고, 50,000명이면 사고."** 지금 나 혼자 눌러서 잘 되는 건 아무 증거가 못 돼요.
> 그래서 사람이 몰릴 앱이라면, 출시 전에 **부하 테스트(가짜 사용자 수백 명이 동시에 들이닥치는 상황을 흉내 내보기, 도구 예: k6)**를 한 번 돌려
> "동시 접속 100명에도 안 죽나"를 확인하면 좋아요. 코치에게 *"동시 사용자 100명이 몰리는 상황을 k6로 흉내 내서 앱이 버티는지 테스트해줘"*라고 시키면 돼요.

## 이렇게 하세요

### 1) 요금 폭탄 방지 (가장 중요)

먼저 **Vercel(호스팅)** 얘기부터. 정직하게 정리하면 이래요.

| 상황 | 실제로 일어나는 일 |
|---|---|
| **Hobby(무료) 플랜에서 한도 초과** | 요금이 청구되는 게 아니라, 그 기능이 **30일 정지**돼요. 즉 무료의 최대 위험은 요금이 아니라 **"앱이 갑자기 멈춤"**이에요. |
| **무료로 광고·결제(상업적 이용)** | 무료 Hobby는 **상업적 이용 금지**예요. 돈 버는 앱이면 **Pro($20)로 올려야** 해요. |
| **Pro(종량제)로 전환한 뒤** | 여기서부터 **진짜 요금 폭탄**이 가능해요. 실제로 DDoS(악의적 트래픽 폭탄) 공격으로 **$23,000이 청구된 사례**가 있어요. |

그래서 **Pro로 올리는 그 첫날** 반드시 이 두 가지를 켜세요.

- **Spend Management(지출 관리)에서 상한 금액**을 설정한다.
- ⚠️ **그리고 "프로젝트 일시정지" 옵션을 따로 켜야** 진짜로 멈춰요. **금액만 설정하면 자동으로 멈추지 않아요** (알림만 오고 계속 과금될 수 있어요). 이 옵션을 켜야 상한에 닿을 때 앱이 정지돼서 폭탄을 막아요.

### 2) Supabase 무료 한도 (DB·데이터)

**Supabase 무료 티어**의 한도예요. 월 1회 대시보드의 **Reports / Usage**에서 확인하세요.

| 항목 | 무료 한도 |
|---|---|
| DB 용량 | **500MB** |
| Egress(밖으로 나가는 데이터) | **5GB / 월** |
| MAU(월간 활성 사용자) | **5만 명** |
| 자동 백업 | **없음** (→ [[제품04-안-무너지게-테스트-모니터링-백업]]) |

> ⚠️ **7일간 요청이 0이면 프로젝트가 자동 일시정지**돼요. 데이터는 보존되지만 **수동으로 재개**해야 다시 살아나요. 방치하다 "왜 갑자기 앱이 죽었지?" 하는 흔한 원인이에요.

### 3) 기본 성능 (느려질 때)

느려지는 대표 원인 네 가지예요. 코치에게 시켜서 손보세요.

- **인덱스(index) = 책 뒤의 색인.** 없으면 DB가 **모든 행을 처음부터 다 훑어요**(느림). 자주 **WHERE(필터)·ORDER BY(정렬)·JOIN(테이블 연결)** 하는 컬럼, 특히 **외래키**에 인덱스를 추가하면 빨라져요. **Supabase Index Advisor**가 느린 쿼리에 딱 맞는 인덱스 SQL을 추천해줘요. ⚠️ 단, 인덱스는 **쓰기를 느리게** 하니 아무 데나 말고 **실제로 느린 쿼리에만**.
- **이미지 = `next/image` 쓰기.** `<img>` 대신 `next/image`를 쓰면 자동으로 **압축·WebP 변환·지연 로딩(lazy load)**이 돼요. **2MB 사진이 180KB로** 줄어드는 식이에요. `<img>` 남발은 대역폭(egress) 낭비예요.
- **N+1 피하기.** 목록 100개를 보여주면서 **작성자를 하나씩 따로 조회**하면 쿼리가 **101번**이에요(1 + 100 = N+1). 이걸 **관계 임베딩/조인 한 번**으로 합치면 쿼리 1번으로 끝나요.
- **페이지네이션 + 필요한 컬럼만.** 한 번에 다 불러오지 말고 **페이지 단위**로 나누고, `select('*')`(전부) 대신 **필요한 컬럼만** 골라 부르세요.

### 4) 웹앱을 모바일로 (판단표로 정하기)

"앱스토어에 올리고 싶다"의 답은 **셋 중 하나**예요. **성급하게 네이티브로 가지 마세요** — 대부분 PWA로 충분해요.

| 방식 | 무엇 | 비용·심사 | iOS 한계 |
|---|---|---|---|
| **PWA** (설치 가능한 웹앱) | 지금 웹앱을 홈화면에 설치·오프라인·푸시 가능하게. `app/manifest.ts` + 서비스워커 + HTTPS(Vercel 기본) | **무료·심사 없음** | 아래 ⚠️ 참고 |
| **래퍼** (Capacitor / PWABuilder / Median) | 웹앱을 앱스토어에 올릴 수 있게 **껍데기만** 씌움 | 스토어 등록비 | 스토어 "존재감"만 필요할 때 |
| **네이티브** (Expo / React Native) | 진짜 앱스토어 앱 | Apple **$99/년**, Google **$25 일회성**, **심사**, 인앱결제 **15~30%** 수수료 | 하드웨어·발견성·고성능 필요 시 |

> ⚠️ **iOS에서 PWA의 한계 (꼭 알기):**
> - **푸시 알림**은 '홈 화면에 설치된 PWA'에서만, 그것도 **iOS 16.4 이상**에서만 돼요.
> - **설치**를 자동으로 띄울 수 없어요. 사용자가 직접 **공유 버튼 → "홈 화면에 추가"**를 눌러야 해요.
> - **하드웨어(NFC·블루투스·AR 등) 접근이 제한**돼요.

**판단표:**

| 내 상황 | 선택 |
|---|---|
| 빠르게 앱처럼 쓰이면 되고, 특수 하드웨어 필요 없음 | **PWA** |
| 앱스토어에 "존재감"만 있으면 됨 | **래퍼** |
| 카메라·NFC·AR·고성능이 필수거나, iOS 사용자 비중이 큼 | **네이티브(Expo)** |

**조언: PWA부터 → 필요하면 래퍼 → 진짜 필요할 때만 네이티브.** 순서대로 올라가세요.

## 🤖 AI(코치)에게 줄 프롬프트

**N+1·페이지네이션 점검:**
```
이 화면이 DB를 과하게 조회(N+1)하는지 점검해줘.
- 목록마다 작성자를 따로 부르고 있으면, 조인 한 번으로 합쳐줘.
- 목록엔 페이지네이션(페이지 단위로 나눠 부르기)을 추가해줘.
- 무엇을 바꿨는지 쉬운 말로 한 줄 설명해줘.
```

**인덱스 추가:**
```
Supabase Index Advisor가 추천하는 인덱스를, 실제로 느린 쿼리에만 적용해줘.
- 아무 컬럼에나 인덱스를 마구 달지 마. 쓰기가 느려지니까.
- 어떤 쿼리가 왜 느렸고, 무슨 인덱스를 왜 달았는지 한 줄로 알려줘.
```

**PWA로 만들기:**
```
이 앱을 홈 화면에 설치 가능한 PWA로 만들어줘(manifest + 서비스워커).
- 설치 후 홈 화면 아이콘으로 열리는지 같이 확인하자.
- 그리고 iOS에서의 제약(푸시·설치·하드웨어)을 미리 솔직하게 알려줘.
```

## ✅ 여기까지 하면 이렇게 보여요

- (Pro라면) **Spend Management 상한 + "일시정지" 옵션**이 켜져 있어요. 요금 폭탄이 막혀요.
- **Supabase Usage**를 어디서 보는지 알고, 무료 한도와 **7일 자동 정지**를 알아요.
- 느린 화면이 **인덱스·조인·페이지네이션·next/image**로 눈에 띄게 빨라졌어요.
- **모바일 방식(PWA/래퍼/네이티브)**을 내 상황에 맞게 **판단**했고, 대개 **PWA부터** 시작해요.
- **안 되면:** 설정·마이그레이션 중 빨간 글씨가 뜨면 전문을 그대로 코치에게. → [[스텝09-막혔을때-에러-읽고-디버깅]]

> 코치는 비용 상한 설정·성능 개선 1건·모바일 방식 결정이 확인되면 `진행상태.md`의 프로덕트 스텝에서 이 모듈을 `- [x]`로 바꾸고 `상태.json`을 갱신합니다.

## ⚠️ 자주 하는 실수

- **Pro에서 '일시정지' 옵션을 안 켜서 요금 폭탄.** 금액만 설정하면 자동으로 안 멈춰요. **일시정지 옵션까지** 켜야 진짜 멈춰요.
- **방치해서 Supabase가 자동 정지.** 7일 무요청이면 죽어요. 가끔 들어가 보거나 이 사실을 기억하세요.
- **`<img>` 남발로 대역폭 낭비.** `next/image`로 바꾸면 압축·WebP로 확 줄어요.
- **인덱스 남발로 오히려 쓰기가 느려짐.** 실제로 느린 쿼리에만 다세요.
- **PWA면 충분한데 성급히 네이티브로 감.** 비용($99/년)·심사·수수료(15~30%)의 벽이 있어요. **PWA부터** 시작하세요.
